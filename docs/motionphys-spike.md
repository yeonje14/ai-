# MotionPhys 특징 추출기: 압축 민감도 측정

README §14.1 백로그 10번(P2-1)의 앞부분. 측정일: 2026-11-14.

> **성능 검증이 아니다. 점수를 내지 않았고 진위를 해석하지 않는다.**
> 진짜 영상 1개를 다시 압축했을 때 특징 값이 얼마나 달라지는지만 쟀다.
> 학습 데이터도 가짜 영상도 없어서 분류기를 학습하지 않았다. 따라서 "압축 때문에 진짜가 가짜로 판정된다"를
> 확인한 것이 아니다. 답할 수 있는 것은 "압축만으로 특징이 몇 % 움직이는가"까지다.
> 영상 1개의 결과이므로 일반화하지 않는다.

정의와 설정은 `docs/motionphys-spec.md`를 본다(공개 코드가 없어 논문을 보고 재구현했고, 숫자 설정은 우리 선택이다).

## 결론

- 세 후보(A 전체 화면, B 얼굴 영역, C Face Motion) 모두 샘플 영상에서 특징을 냈다. 같은 입력을 두 번 실행한 차이는 0이다.
- **이 영상에서는 압축보다 표본 프레임의 위치가 특징을 더 크게 움직였다.** 압축하지 않고 표본을 한 프레임(1/30초) 뒤로 민 대조군에서 jerk 특징의 변화(중앙값)는 A 6.4%, B 8.4%, C 9.5%였다. CRF 34에서는 A 2.8%, B 3.3%, C 8.5%였다. 재압축의 영향이 "같은 영상을 조금 다르게 뽑았을 때의 흔들림"보다 작거나 비슷하다.
- **jerk가 세 물리량 가운데 가장 민감하지는 않았다.** 대부분의 조건에서 곡률 특징이 가장 많이 움직였다(A에서 CRF 34: 곡률 5.9%, 각속도 3.6%, jerk 2.8%). 식 (5)의 분모 ‖v‖³ 때문에 느리게 움직이는 점의 곡률이 불안정하다.
- **24프레임 스케일은 불안정하다.** 48프레임에서 클립이 2개뿐이다. A의 "jerk 평균의 중앙값"은 CRF 28에서 −44%, CRF 34에서 −53%, 대조군에서 +71%였다. 8·12프레임 스케일에서는 같은 값이 ±7% 안이었다.
- **C(Face Motion)가 가장 불안정하다.** 화질 손실이 가장 적은 CRF 20에서도 곡률 특징의 변화(중앙값)가 17%였고, 입술 영역의 곡률 대표값은 +52% ~ +77% 움직였다. 특징점 추정의 떨림이 지배적인 것으로 보인다(원인은 따로 확인하지 않았다).
- 유효 궤적 수와 추적 성공률은 압축에 거의 영향을 받지 않았다(A에서 2,140~2,155개, 성공률 85%).

해석의 한계는 아래 "읽을 때 주의할 점"에 적었다.

## 압축 조건

FFmpeg 8.0.1의 소프트웨어 인코더 libx264로 화질(CRF)만 바꿨다. 해상도와 프레임률은 그대로다. 하드웨어 인코더는 쓰지 않았다. **실제 YouTube의 재인코딩과 같다고 주장하지 않는다.**

```bash
ffmpeg -i <원본> -map 0:v:0 -c:v libx264 -preset medium -crf <20|28|34> -pix_fmt yuv420p -an <출력>
```

| 조건 | 코덱 | 비트레이트 | 크기 |
|---|---|---|---|
| 원본 | HEVC | 2,785 kbps | 3,631,959바이트 |
| CRF 20 | H.264 | 5,873 kbps | 7,659,657바이트 |
| CRF 28 | H.264 | 2,031 kbps | 2,649,264바이트 |
| CRF 34 | H.264 | 946 kbps | 1,233,891바이트 |
| 대조군 | (원본 그대로) | – | – |

- CRF 20은 원본보다 파일이 크다. 원본이 이미 낮은 비트레이트라서, CRF 20은 "거의 손실 없이 코덱만 바꾼 것"에 가깝다.
- **대조군**은 압축하지 않은 원본에서 구간의 시작만 한 프레임(1/30초) 뒤로 민 것이다. 뽑히는 48프레임이 조금씩 달라진다. 같은 진짜 영상에서 표본 위치만 달라져도 특징이 얼마나 움직이는지 보려는 기준이다.
- 변환본은 `data/research/motionphys-spike/`(Git 제외)에 있다.

## 측정 방법

- 조건마다 세 후보의 특징을 뽑고, 원본의 특징과 견줬다.
- **상대 변화** = (조건의 값 − 원본의 값) / |원본의 값|. 물리량(곡률, 각속도, jerk)마다 그 물리량에 속한 특징들(A·B는 168개, C는 504개)의 |상대 변화|의 중앙값과 90번째 백분위를 적었다.
- **대표값**은 "궤적별 평균의 궤적 간 중앙값"(`L8.jerk.mean.median` 등)이다. 그 물리량의 전형적인 크기다.
- 같은 원본을 두 번 실행해 차이가 0인지 확인했다.
- 압축본은 Shi–Tomasi가 고르는 코너가 조금 달라진다. 그래서 변화에는 "같은 점의 좌표가 흔들린 것"과 "다른 점이 뽑힌 것"이 섞여 있다. 둘을 나눠 재지 않았다.

## 읽을 때 주의할 점

1. **"압축이 진짜를 가짜처럼 보이게 하는가"에는 아직 답하지 못한다.** 분류기가 없고 가짜 영상의 특징 분포도 없다. 특징이 3% 움직이는 것이 판정을 바꿀 만큼 큰지는 진짜와 가짜의 차이가 얼마인지 알아야 판단할 수 있다. 데이터가 생기면 같은 영상의 원본과 압축본에 대한 점수 차이를 직접 재야 한다(README §13.2의 C1~C5).
2. **대조군이 더 크게 움직였다는 것은 "압축은 괜찮다"가 아니라 "특징 자체가 흔들린다"는 뜻이다.** 같은 진짜 영상에서 표본을 1/30초 옮겼을 뿐인데 jerk 특징이 6~10% 달라졌다. 영상 간 차이를 보기 전에 영상 안의 흔들림이 이만큼 있다.
3. **프레임 간격이 0.22초다.** 48프레임을 10.4초에 걸쳐 뽑았으므로 6~7프레임에 한 장이다. 인접 프레임 사이의 압축 잡음보다 실제 움직임이 훨씬 크게 잡힌다(A에서 걸음당 이동의 중앙값 1.4~1.7px, 처리 해상도 기준). 1~2초의 짧은 구간에서는 연속 프레임을 쓰게 되어 움직임이 작아지고 추적 잡음의 비중이 커진다. **짧은 구간에서는 압축의 영향이 다를 수 있고 이번에 재지 않았다.**
4. **처리 해상도를 640px로 줄였다.** 축소가 압축 잡음을 평균해 줄였을 수 있다. 원본 해상도에서는 재지 않았다.
5. **원본이 이미 압축된 파일이다.** 촬영 원본에서 시작한 측정이 아니다.
6. **영상 1개, 조건당 1회다.** 야외에서 손으로 든 카메라라 화면 전체가 움직인다(유효 궤적의 87~100%가 "움직인 궤적"). 고정 카메라의 말하는 사람 영상에서는 정지한 배경 점이 많아져 곡률과 각속도의 분포가 달라질 것이다(`docs/motionphys-spec.md` §2).
7. **이 영상에는 발화가 없다.** 입술 영역의 값은 말할 때의 움직임이 아니다.

## 데이터 없이 확인한 것 (단위 테스트)

`tests/test_motionphys_kinematics.py`, `tests/test_motionphys_extract.py`, `tests/test_motionphys_train.py`.

- **합성 궤적**: 등속 직선(곡률·jerk 0), 등속 원운동(곡률 cos(θ/2)/R, 각속도 θ, jerk 일정), 등가속도(jerk 0)가 식대로 나온다.
- **떨리는 운동**: 위치 잡음 σ를 더하면 jerk 평균이 약 5.6σ로 커지고(오차 3% 이내), 같은 잡음이 속도에 주는 영향의 √10배다. 떨리는 궤적은 jerk 평균 특징이 매끄러운 궤적의 10배를 넘는다.
- **식의 성질**: 정지한 점의 각속도가 π/2가 되는 것, 아주 작은 움직임에서 곡률이 100배 이상 커지는 것.
- **차원과 이름**: 24, 168, 504차원. 이름과 값의 위치가 맞는지. 궤적 순서와 무관한지.
- **합성 영상**: 알려진 이동량(1.5, 0.5px/프레임)을 추적기가 0.1px 안으로 복원한다. 떨리게 움직인 무늬는 jerk 대표값이 매끄러운 무늬의 3배를 넘는다. 정지한 영상은 `insufficient_motion`, 특징 `null`.
- **얼굴 후보**: 샘플 영상에서 B 504차원, C 1,512차원. 얼굴이 없는 합성 영상에서는 `tracking_failed`. 모델 파일의 sha256이 다르면 실행 거부.
- **LightGBM 스크립트**: 신호를 심은 합성 특징으로 학습 → dev·test 점수 파일 → 평가 파이프라인(`fit-threshold`, `evaluate`)까지 이어진다. train의 점수와 external의 점수는 내지 않는다. 누수가 있는 manifest와 외부 평가 자료를 train에 넣은 manifest는 학습을 거부한다. **합성 데이터에서의 동작 확인이며 성능이 아니다.**
