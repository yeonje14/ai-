HiDF 배포 README는 실제·가짜 각 4,241개와 파일명 `(base_video_id)_(target_image_id).mp4`를 명시한다. CSV 예시는 이미지 ID와 인구통계 열이다. ZIP 목록으로 원본·합성본 대응을 확인한다. 연구진의 이전 공개 원고에는 Reface 사용, YouTube 영상의 3초 클립화와 FakeAVCeleb 실제 영상 사용이 명시돼 있다. 현재 배포본의 클립별 출처, 도구 버전·가중치, 고유 인물 수는 별도 확인 사항이다. [배포 README](https://github.com/DSAIL-SKKU/HiDF) · [Zenodo](https://zenodo.org/records/16140829) · [공개 원고 §3.1](https://openreview.net/pdf?id=XhyCPEnlCa)

LipSync-A 공개 카드에서 오디오 구동의 `0_real`은 얼굴 신원 원천 영상, 비디오 구동의 `0_real`은 구동 영상이다. 가짜 10,573개 중 9,474개에 짝이 있다. 이 수치로 고유 화자 수를 계산할 수 없다. 모든 생성기의 음성 출처·음성 유무를 한 폴더의 설정으로 추정하지 않는다. [LipSync-A 카드](https://huggingface.co/datasets/AnsonShe/LipSync-A)

## 파일럿 순서

1. **개발 표본을 먼저 구분한다.** 배포 버전·이용 조건·해시를 기록한다. HiDF는 영상 ZIP 두 개와 CSV만 약 1.56GB다. LipSync-A는 우선 파일 목록·카드·선택 메타데이터의 구조를 확인한다. 배포 버전을 고정하고 실제·가짜 양쪽 경로가 존재하는 행만 뽑는다. 조회 실패나 빈 계보는 미확인으로 남긴다. 원본 미디어는 Git 밖의 연구 데이터 영역에 둔다.
2. **독립 그룹을 계산한다.** 원본 녹화, 확인된 인물, 같은 얼굴·구동 클립이나 음성 재사용이 분할을 가로지르지 않게 연결한다. 파일명 stem이나 폴더명을 인물 ID로 대입하지 않는다. 참가자를 모르면 어느 수준까지 독립성을 확인했는지 적는다. 연결 후 고유 그룹 수와 최대 그룹 비중을 보고한다. 한 그룹이 내부 영상의 25%를 넘으면 현행 학습기가 거부한다. 공식 분할이 있으면 보존하고 충돌을 보고한다.
3. **각 자료에서 약 10쌍을 먼저 읽고, 이후 최대 50쌍으로 늘린다.** 개발에 배정된 그룹에서 시드를 고정해 추출한다. 폴더 앞부분만 뽑거나 같은 원본을 중복 집계하지 않는다. 해상도·길이·코덱·실제 선택된 오디오 트랙·디코딩 오류를 기록하고, 표본 부족도 그대로 표시한다. 기존 Gate와 세 축을 원본에 실행해 자료·생성기·클래스별 분모, 통과 건수, 보류 사유와 판정 제공 비율을 기록한다.
4. **현재 입력 계약을 적용한다.** Gate의 기본 최소 구간은 1초, 최소 짧은 변은 360px이며 얼굴 크기·선명도·발화 등도 검사한다. WaveRep은 짧은 변 504px 이상이어야 한다. SyncNet은 Gate 적합 구간에서 25fps 기준 50프레임과 유효 트랙을 따로 검사한다. 영상 전체가 2초여도 통과를 보장하지 않는다. 축 하나가 실패해도 다른 축은 자신의 조건으로 계속 처리한다. 빠진 점수는 `null`로 둔다. SyncNet은 동기화 보조 지표다.
5. **지름길을 진단한다.** 해상도, 오디오 유무, 코덱, 선행 무음 등 메타데이터만으로 라벨을 예측하는 AUC를 독립 그룹 단위로 계산한다. 자료별 결과와 가능하면 생성기별 결과, 표본 수, 불확실성을 함께 기록한다. 클래스 차이 10%p와 AUC 0.70은 추가 조사를 시작할 제안값이다. 작은 파일럿의 낮은 AUC나 낮은 통과율 차이가 편향 부재를 입증하지 않는다. AUC 불확실성을 일률적으로 ±0.1이라 쓰지 않는다.
6. **학습 제안은 파일럿 뒤에 한다.** 정식 대체를 제안할 때는 이용 조건, 그룹 누수, 외부 자료와의 계보 중복, 실제 사용 가능한 그룹 수를 제시하고 DESIGN §15.3 결정 6 변경을 먼저 제안한다. 결합 후보와 임계값은 dev에서 고정하고 내부 test는 한 번만 확인한다. 파일럿·전처리 선택에 쓴 그룹은 test에서 제외한다. 양쪽 자료를 모두 개발에 썼다면 교차 데이터 성능에는 개발 관여 범위를 표시한다.

### 부록 스크립트와 원본 명령을 적용할 때의 정정

- 원문 `lsa-scan`은 파일 목록 조회 실패 때 모든 행에 실제 짝이 있다고 간주한다. 제외 생성기도 출력 목록에서 일괄 차단하지 않는다. 이 결과를 학습 목록으로 사용하면 안 된다. 선택 메타데이터의 실제 최상위 구조와 필드명, 제외 규칙, 빈 ID, 중복, 요청 개수 부족을 검사해야 한다.
- 원문 `audit`은 LipSync-A의 `생성기:파일명`을 그룹으로 쓴다. 다른 폴더에서 재사용한 인물이 서로 다른 폴드에 들어갈 수 있다. 공통 manifest에서 계산한 그룹 ID를 사용하고, 독립 그룹이나 두 클래스가 부족하면 AUC를 미산출로 둔다. HiDF도 원본뿐 아니라 공여 자료의 재사용을 확인한다.
- `ffprobe` 실패를 해상도 0·무음 영상으로 기록하지 않는다. 오류와 결측을 별도 집계한다. 무음 검출의 여집합은 소리가 있는 시간이며 발화 비율은 실제 VAD로 확인한다. 서비스와 같은 오디오 트랙 선택 규칙을 적용한다.
- 원본 명령의 오디오 단독 `silenceremove`는 영상보다 소리를 앞당겨 SyncNet이 측정할 시간차를 바꾼다. 원본이 기본 조건이다. 별도 통제 실험을 한다면 사전 고정한 동일 시간 구간을 영상·음성 양쪽에 적용하고 재인코딩 전후 시간 정렬과 결과를 각각 기록한다. 외부 평가 규약은 파일럿 결과에 맞춰 바꾸지 않는다.
- 파일럿 TSV의 숫자 라벨은 중간 표현이다. 저장소의 공통 manifest는 CSV와 `real`·`fake` 라벨을 사용한다. 메타데이터 JSONL은 어댑터의 입력이다. 현재 `configs/datasets/hidf.json`은 미확인 상태이고 LipSync-A 설정은 아직 없다. 실제 행·경로 대응을 확인하고 설정 및 필요한 변환을 검증한 뒤 `python -m training.datasets.adapters`, `python -m training.features.extract` 순서로 진행한다. 설치 전 기존 conda·모델별 venv를 사용하고, 파일럿을 위해 기본 환경 패키지를 일괄 갱신하지 않는다.

## 외부 평가와 오탐률

MAVOS-DD 공식 open-set model에서 추가된 생성기는 Sonic·HiFiFace·Roop이다. 직접 일치하는 항목은 학습·개발에서 제외한다. 논문은 InSwapper를 기본 생성기로 따로 분류한다. FaceFusion은 여러 모델을 실행하는 도구다. 같은 가중치 계열까지 제외하는 더 엄격한 실험을 할 때는 버전·모델·가중치 근거를 별도로 적고 확인 못한 항목은 해당 실험에서 보류한다. 미지 생성기 주장은 TRINITY에서 통제한 학습·개발 범위를 명시한다. HiDF 제외 비교와 모델 선택은 개발 단계에서 고정하고 외부 점수로 조합을 고르지 않는다. [MAVOS-DD 논문](https://openreview.net/pdf?id=XHSKSNIjLf) · [BabelFake 부록 E](https://arxiv.org/html/2610.06339v1)

FPR 관문은 점수가 나온 실제 영상으로 계산한다. 저장소 함수에서 n은 이 영상들의 독립 그룹 수, k는 n × 영상 단위 FPR이며 소수도 가능하다. 그룹 bootstrap 상한과 CP 방식 상한 중 큰 값이 10% 이하여야 한다. 점수 미산출 비율과 그 사유도 보고한다.

| n | 정수 k로 가정했을 때 CP 상한이 10% 이하인 최대 k | 그때의 CP 상한 |
|---:|---:|---:|
| 36 | 0 | 9.74% |
| 59 | 1 | 9.09% |
| 99 | 3 | 8.60% |
| 100 | 4 | 9.93% |
| 150 | 7 | 9.38% |

실제 영상 오탐 건수와 k가 같아지는 예는 그룹당 판정된 실제 영상이 한 개일 때다. 100·150그룹은 필수 최소치가 아니다. 59명도 전원이 test에 들어간다는 보장이 없으며, 총 참가자 수만으로 관문 통과 가능 여부를 단정할 수 없다. BabelFake의 70/10/20은 공식 분할 비율이다. 496명의 20%는 약 99명이지만 실제 test 참가자 수, 계보 연결 후 그룹 수, 각 모델이 점수를 낸 그룹 수는 각각 다를 수 있다. test 결과에 맞춰 다시 나누지 않는다. [BabelFake §6.1](https://arxiv.org/html/2610.06339v1) · [저장소 평가 규칙](training-pipeline.md)

## 일정과 보고 문구

DeepSpeak 신청은 기존 기록에 따라 대기 중이다. BabelFake는 기관 검증·비상업 연구 이용 계약 조건이 명시돼 있고 공개 신청 창구는 이번 검토에서 확인하지 못했다. 문의는 접근 경로, 학부생·지도교수 자격, 허용 용도, 메타데이터 예시와 부분 다운로드 여부부터 묻는다. ‘Roop 계열을 모두 미지로 유지한다’는 문구는 공식 평가 정의와 구분한다. 지도교수명·산학 협력 및 가용 용량은 실제 상황 확인 후 기재한다. 12월 8일 재문의와 2027년 1월 15일 계획 동결은 일정 제안이다.

현재 발표 가능한 결론은 “공개 얼굴 교체·립싱크 자료를 개발 파일럿 후보로 선정했다. 외부 평가 분할을 잠갔고, 데이터별 오탐률과 축별 처리 가능 비율은 미측정이다.” 실측 뒤에는 자료·생성기·분할·독립 그룹 수와 함께 결과를 보고한다. 웹캠 자료에서 얻은 오탐률을 YouTube 실사용 전체에 일반화하려면 별도의 대표성 검증이 필요하다.
