# Seamless 파일럿 입력 전처리 규칙

2026-11-25 · 사용자 결정(pilot#0 첫 쌍 결과 근거, `docs/seamless-first-pair.md` §6). **서비스 제한은 바꾸지 않는다.**
이 규칙은 Seamless 파일럿의 모델 입력을 만드는 방법만 고정한다. 결과를 보기 전에 커밋한다.
아래 결과 절은 규칙을 커밋한 뒤 pilot#0에 적용해 채운다.

**Seamless의 original 조건은 카메라 원본이 아니라 이 전처리(1080×1920, CRF 20) 결과다. 이후 압축 조건은 그 위에 적용된다.**

## 1. 창 선택

공통 정의는 다음과 같다.
- 창 길이는 **25초**다.
- 발화량은 Seamless 공식 Meta VAD(`metadata:vad`)와 창이 겹치는 시간의 합이다. Gate VAD는 결과물이므로 쓰지 않는다.
- 시작점 s의 후보는 아래 값 가운데 허용 범위 안에 있는 것들이다. 발화량은 s에 대해 구간마다 직선으로 변하므로, 이 후보들 가운데 최댓값이 있다.
  - VAD 구간 시작
  - VAD 구간 끝 − 25
  - 허용 범위의 양 끝
- 발화량은 마이크로초로 반올림해 비교한다. **같으면 앞쪽(작은 s)을 고른다.**

| 창 | 누구의 VAD | 허용 범위(시작점 s) | 없을 때 |
|---|---|---|---|
| **A 얼굴 창**(실제·합성 공통 영상 구간) | A | `[max(영상 시작, 0), min(영상 끝, WAV 끝) − 25]` | `window_unavailable` |
| **B 얼굴 창**(B를 독립 실제 영상으로 확인) | B | 같은 방식으로 B 파일에서 | `window_unavailable` |
| **A 구동 음성 창**(같은 화자 합성용) | A | `[0, WAV 끝 − 25]` 가운데 **A 얼굴 창과 겹치지 않는** s. 즉 `s + 25 ≤ 얼굴 시작` 또는 `s ≥ 얼굴 끝`이고, 경계가 맞닿는 것은 허용한다 | `same_speaker_unavailable` |
| **B 구동 음성 창**(상대 화자 합성용) | B | B 얼굴 창을 그대로 쓴다 | B 얼굴 창이 없으면 `window_unavailable` |

- 창이 없어도 **쌍을 바꾸지 않는다.** 그 조건만 보류로 기록하고 나머지 조건은 진행한다.
- A·B는 같은 대화의 같은 시간축이다(첫 쌍에서 영상과 WAV 길이가 같음을 확인했다).
- **구동 음성 창은 이번에는 계산해서 기록만 한다. 합성은 하지 않는다**(지도교수 확인 대기).

## 2. 자르기와 최종 인코딩

- **입력.** 원본 MP4의 영상 스트림과 같은 참가자의 WAV 하나를 쓴다. MP4 자체 오디오는 쓰지 않는다.
- **자르기.** 두 입력을 한 FFmpeg 명령에 넣고, 출력 쪽에서 `-ss s -t 25`로 두 스트림을 같은 시간축에서 함께 자른다. 원본의 영상·오디오 시작 시각 관계(0.033초 대 0초)는 바꾸지 않는다.
- **영상.** 기존 압축 에뮬레이터 프로파일 `x264-crf20-1080p`의 설정을 그대로 쓴다(`training/emulator/profiles.py`, 코드에서 같은 객체를 읽는다).
  - libx264, preset medium, CRF 20, threads 4
  - 짧은 변 1080(bicubic), 1080×1920, yuv420p
  - fps는 원본 그대로(30000/1001). bitexact 플래그를 쓴다.
  - 하드웨어 인코더는 쓰지 않는다.
- **오디오.** WAV를 AAC-LC 48kHz 모노 192kbps로 인코딩한다.
- **컨테이너.** MP4(`+faststart`), 메타데이터 제거.
- **적용 범위.** 실제 조건과 이후 두 합성 조건 모두 **같은 최종 인코딩**을 거친다. 합성기가 낸 출력도 이 단계에서 다시 인코딩한다.
  - 영상: 같은 A 얼굴 창 구간, 같은 설정
  - 오디오: 각 조건의 구동 음성 창
  - 합성기가 추가로 거친 인코딩은 따로 기록한다.
- **기록.** 창(시작·끝·발화량·후보 수), 입출력 SHA-256, FFmpeg 버전, 명령 인자, 처리 시간, 출력 크기, 출력 ffprobe.

## 3. 보존·삭제

### 4.4 B `no_mouth_movement` 원인 진단 (2026-11-26, 서비스 코드 변경 없음)

**방법.**
- A·B 전처리 MP4에 Gate와 같은 모델 파일(해시 일치)과 `GateConfig` 기본값을 썼다.
- 5fps 표본 125개마다 다음을 셌다.
  - 얼굴 검출기(BlazeFace short-range)의 성공 여부, 점수, 박스 높이
  - Face Landmarker를 전체 프레임에 돌렸을 때의 성공 여부
  - 같은 프레임을 검출 박스 중심의 정사각형(박스 긴 변의 2–6배, 프레임 안으로 자름)으로 잘라 넣었을 때의 성공 여부
- 프레임, crop, 특징점 좌표는 저장하지 않았다.
- 진단 스크립트는 일회성이라 저장소에 넣지 않았다. 같은 측정은 Gate 개선 작업의 비교 스크립트로 다시 한다.

| 항목 | A 전처리 | B 전처리 |
|---|---:|---:|
| 검출기 성공(표본 125개 중) | 124 | 90 |
| 검출 점수 최소 / 중앙 / 최대 | 0.5 / 0.8 / 0.9 | 0.5 / 0.6 / 0.7 |
| 검출 얼굴 높이 최소 / 중앙 / 최대(px) | 221 / 251 / 474 | 235 / **286** / 360 |
| 특징점 성공: 전체 프레임 (검출기 성공 표본 중) | 118 / 124 | **21 / 90** |
| 특징점 성공: 박스 2배 crop | 119 | **90** |
| 3배 | 121 | 90 |
| 4배 | 122 | 90 |
| 5배 | 121 | 87 |
| 6배 | 121 | 72 |
| 전체 프레임, 특징점 모델 임계값 0.3 / 0.1 (표본 125개 전체 기준, 기본 0.5) | 118 / 119 | 25 / 32 |
| 고개 돌림 근사: \|코 − 두 눈 중점\| ÷ 눈 사이 거리(중앙값) | 0.166 | 0.137 |
| 얼굴 박스 밝기 평균 / 표준편차(중앙값) | 120.2 / 40.9 | 113.3 / 49.8 |

**확인한 것.**
1. **B의 얼굴은 픽셀 크기로는 작지 않다.**
   - 검출 높이 중앙값은 286px로 A(251px)보다 크다. Gate 기준(96px, 주된 얼굴 108px)도 넘는다.
   - 고개 돌림 근사와 밝기도 A와 비슷하다.
2. **실패한 단계는 입 벌림 측정(Face Landmarker)이다.**
   - 검출기가 얼굴을 찾은 90개 표본 중, 전체 프레임으로는 21개만 특징점을 얻었다.
   - 같은 표본을 얼굴 주변으로 자르면 90개 모두 얻었다.
   - 자르는 범위를 넓힐수록 성공이 줄었다(4배 90 → 5배 87 → 6배 72 → 전체 21). 범위가 넓을수록 얼굴이 입력 이미지에서 차지하는 비율은 작아진다.
   - 임계값을 0.1까지 낮춰도 32개였다.
   - 따라서 직접 원인은 **세로 전신 프레임에서 얼굴이 이미지 전체에 비해 작다**는 것이다. 얼굴 높이는 긴 변 1920px의 약 15%다. 이 때문에 특징점 모델이 전체 프레임에서 결과를 내지 못했다.
3. **A는 같은 비율에서도 성공했다.**
   - 둘의 차이는 검출 점수(중앙값 0.8 대 0.6)에서도 보인다. B가 경계에 더 가까운 이유는 확인하지 못했다.
   - Face Landmarker 번들 안의 검출 모델은 Gate 검출기 파일과 SHA-256이 같다(`b4578f35…`, short-range). 그런데 단독 검출기는 90개, 특징점 모델은 21개를 얻었다. 그 내부 이유는 확인 필요.
4. **원인 코드가 "입이 움직이지 않음"과 "입을 잴 수 없음"을 구분하지 않는다.**
   - 측정이 없는 표본은 `None`이고, 시계열은 그 자리에서 끊긴다(`split_chunks`).
   - B는 이어진 측정이 짧아 반전이 1번뿐이었다(`mouth_summary.reversals=1`). 그래서 주된 얼굴이 하나인 음성 구간이 모두 `no_mouth_movement`가 됐다.
   - 이 코드는 `out_of_scope` / `not_applicable`로 나가므로 "말하는 사람이 없는 영상"처럼 읽힌다.
   - 검출기 자체가 놓친 표본도 35개 있다(`no_face_detected` 4.8초).
5. **서비스 영향.**
   - 사용자 YouTube 영상 가운데 세로 전신 구도에서 같은 일이 생길 수 있다.
   - 근거는 영상 1개(B)이며, 일반화는 미검증이다.
