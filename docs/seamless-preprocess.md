# Seamless 파일럿 입력 전처리 규칙

2026-11-25 · 사용자 결정(pilot#0 첫 쌍 결과 근거, `docs/seamless-first-pair.md` §6). **서비스 제한은 바꾸지 않는다.**
이 규칙은 Seamless 파일럿의 모델 입력을 만드는 방법만 고정한다. 결과를 보기 전에 커밋한다.
아래 결과 절은 규칙을 커밋한 뒤 pilot#0에 적용해 채운다.

**Seamless의 original 조건은 카메라 원본이 아니라 이 전처리(1080×1920, CRF 20) 결과다. 이후 압축 조건은 그 위에 적용된다.**

## 1. 창 선택

공통 정의는 다음과 같다.
- 창 길이는 **25초**다.
- 발화량은 Seamless 공식 Meta VAD(`metadata:vad`)와 창이 겹치는 시간의 합이다. Gate VAD는 결과물이므로 쓰지 않는다.
- 시작점 s의 후보는 아래 값 가운데 허용 범위 안에 있는 것들이다. 발화량은 s에 대해 구간마다 직선으로 변하므로, 이 후보들 가운데 최댓값이 있다.
  - VAD 구간 시작
  - VAD 구간 끝 − 25
  - 허용 범위의 양 끝
- 발화량은 마이크로초로 반올림해 비교한다. **같으면 앞쪽(작은 s)을 고른다.**

| 창 | 누구의 VAD | 허용 범위(시작점 s) | 없을 때 |
|---|---|---|---|
| **A 얼굴 창**(실제·합성 공통 영상 구간) | A | `[max(영상 시작, 0), min(영상 끝, WAV 끝) − 25]` | `window_unavailable` |
| **B 얼굴 창**(B를 독립 실제 영상으로 확인) | B | 같은 방식으로 B 파일에서 | `window_unavailable` |
| **A 구동 음성 창**(같은 화자 합성용) | A | `[0, WAV 끝 − 25]` 가운데 **A 얼굴 창과 겹치지 않는** s. 즉 `s + 25 ≤ 얼굴 시작` 또는 `s ≥ 얼굴 끝`이고, 경계가 맞닿는 것은 허용한다 | `same_speaker_unavailable` |
| **B 구동 음성 창**(상대 화자 합성용) | B | B 얼굴 창을 그대로 쓴다 | B 얼굴 창이 없으면 `window_unavailable` |

- 창이 없어도 **쌍을 바꾸지 않는다.** 그 조건만 보류로 기록하고 나머지 조건은 진행한다.
- A·B는 같은 대화의 같은 시간축이다(첫 쌍에서 영상과 WAV 길이가 같음을 확인했다).
- **구동 음성 창은 이번에는 계산해서 기록만 한다. 합성은 하지 않는다**(지도교수 확인 대기).

## 2. 자르기와 최종 인코딩

- **입력.** 원본 MP4의 영상 스트림과 같은 참가자의 WAV 하나를 쓴다. MP4 자체 오디오는 쓰지 않는다.
- **자르기.** 두 입력을 한 FFmpeg 명령에 넣고, 출력 쪽에서 `-ss s -t 25`로 두 스트림을 같은 시간축에서 함께 자른다. 원본의 영상·오디오 시작 시각 관계(0.033초 대 0초)는 바꾸지 않는다.
- **영상.** 기존 압축 에뮬레이터 프로파일 `x264-crf20-1080p`의 설정을 그대로 쓴다(`training/emulator/profiles.py`, 코드에서 같은 객체를 읽는다).
  - libx264, preset medium, CRF 20, threads 4
  - 짧은 변 1080(bicubic), 1080×1920, yuv420p
  - fps는 원본 그대로(30000/1001). bitexact 플래그를 쓴다.
  - 하드웨어 인코더는 쓰지 않는다.
- **오디오.** WAV를 AAC-LC 48kHz 모노 192kbps로 인코딩한다.
- **컨테이너.** MP4(`+faststart`), 메타데이터 제거.
- **적용 범위.** 실제 조건과 이후 두 합성 조건 모두 **같은 최종 인코딩**을 거친다. 합성기가 낸 출력도 이 단계에서 다시 인코딩한다.
  - 영상: 같은 A 얼굴 창 구간, 같은 설정
  - 오디오: 각 조건의 구동 음성 창
  - 합성기가 추가로 거친 인코딩은 따로 기록한다.
- **기록.** 창(시작·끝·발화량·후보 수), 입출력 SHA-256, FFmpeg 버전, 명령 인자, 처리 시간, 출력 크기, 출력 ffprobe.

## 3. 보존·삭제

- 원본(MP4·WAV·JSON·NPZ)은 남은 파일럿 단계를 위해 보존한다.
- 전처리 결과물은 다시 만들 수 있지만, 원본 대비 비교를 위해 pilot 폴더에 보존한다.
- 모델 실행 작업 폴더는 끝나면 지운다.
- 모두 Git 밖 `data/research/seamless/`에 둔다.
