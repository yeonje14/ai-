# TRINITY 디자인 시스템

README §14.1 백로그 13번(P3-1)의 앞부분. 작성일: 2026-11-14. 구현: `app/lib/design/`.

> 화면에 나오는 결과는 모두 가상 데이터다. 실제 모델이 연결되기 전까지 모든 화면 상단에 "모델 미연결 · 가상 데이터" 띠를 둔다.

## 원칙

1. **진위를 확정하는 것처럼 보이지 않는다.** 결과 요약은 "의심 신호 발견 / 의심 신호 낮음 / 판단 보류" 세 가지뿐이다. 숫자 점수와 퍼센트를 쓰지 않는다.
2. **"의심 신호 낮음"에 초록을 쓰지 않는다.** 초록은 안전·진짜로 읽힌다. 무채색(#D4D4D4)을 쓰고, "진짜 영상이라는 뜻이 아닙니다"라는 문구를 함께 둔다.
3. **색만으로 뜻을 전하지 않는다.** 상태에는 항상 글자 라벨이 있다.
4. **노년층이 읽을 수 있어야 한다.** 큰 글자, 높은 대비, 넓은 터치 영역, 시스템 글자 크기 확대 대응.
5. **없는 값은 없다고 말한다.** `null`은 "값 없음"으로 보여 준다. 0으로 바꾸지 않는다.

## 색

| 토큰 | 값 | 쓰는 곳 | 배경 위 대비 | 표면 위 대비 |
|---|---|---|---|---|
| `background` | `#0A0A0A` | 화면 배경 | – | – |
| `surface` | `#141414` | 카드, 안내 박스, 고지 띠, 입력란 | – | – |
| `border` | `#2A2A2A` | 구분선, 카드 테두리(장식) | 1.4:1 | 1.3:1 |
| `text` | `#FAFAFA` | 본문, 제목 | 19.0:1 | 17.7:1 |
| `textSecondary` | `#9A9A9A` | 보조 텍스트, "분석 대상 아님"·진행 상태 라벨 | 7.0:1 | 6.5:1 |
| `accent` | `#FF3D00` | **"의심 신호 발견"에만** | 5.6:1 | 5.2:1 |
| `warning` | `#FACC15` | "판단 보류", "영상 접근 불가", 작업 실패, 주의 안내 | 12.9:1 | 12.0:1 |
| `neutral` | `#D4D4D4` | "의심 신호 낮음" | 13.4:1 | 12.4:1 |

- 대비는 WCAG 2.x 식으로 계산한 값이다(`app/lib/design/tokens.dart`의 `contrastRatio`, 테스트가 4.5:1 이상을 확인한다).
- `border`(#2A2A2A)는 대비가 낮아 **장식용 구분선에만** 쓴다. 눌러서 조작하는 요소(입력란, 보조 버튼)의 테두리는 `textSecondary`나 `text`를 쓴다(3:1 이상).
- **강조색을 버튼이나 장식에 쓰지 않는다.** 주황이 보이면 "의심 신호 발견"이라는 뜻이어야 한다. 그래서 기본 버튼은 밝은 바탕(#FAFAFA)에 어두운 글자다.
- 초록 계열 색은 토큰에 없다.

## 글꼴

| 용도 | 글꼴 | 굵기 |
|---|---|---|
| 본문·제목(라틴) | Inter Tight | 400, 700 |
| 한글 | Noto Sans KR (대체 글꼴로 연결) | 400, 700 |
| ID·상태 값·원시 지표·고지 띠 | JetBrains Mono | 400 |

| 스타일 | 크기 | 굵기 | 줄간격 |
|---|---|---|---|
| `display` (화면 제목) | 26 | 700 | 1.35 |
| `title` (구역 제목) | 20 | 700 | 1.4 |
| `body` | 16 | 400 | 1.5 |
| `bodyStrong` | 16 | 700 | 1.5 |
| `label` (상태 라벨) | 13 | 700 | 1.5 |
| `secondary` | 13 | 400 | 1.5 |
| `mono` | 13 (값에는 16) | 400 | 1.5 |

- 본문은 16 이상, 보조 텍스트는 13 이상이다. 13보다 작은 글자는 없다.
- 제목의 줄간격(1.35, 1.4)은 본문(1.5)보다 좁다. 줄간격 1.5는 본문과 보조 텍스트에 적용했다.
- 굵기는 400과 700만 쓴다. 다른 굵기를 쓰려면 글꼴 파일을 추가해야 한다.

### 글꼴 파일

`app/assets/fonts/`에 실제로 쓰는 굵기 5개만 넣었다(합계 약 4.9MB). 실행 중에 글꼴을 내려받지 않는다.

| 파일 | 크기 | sha256 앞 12자 |
|---|---|---|
| `InterTight-Regular.ttf` | 58,296바이트 | `045c3ecbfb1b` |
| `InterTight-Bold.ttf` | 58,712바이트 | `a7f53e49ddeb` |
| `JetBrainsMono-Regular.ttf` | 57,800바이트 | `473c93ad62d8` |
| `NotoSansKR-Regular.ttf` | 2,475,164바이트 | `3ff71be5e803` |
| `NotoSansKR-Bold.ttf` | 2,474,496바이트 | `245bef46ff8b` |

- **라이선스**: 세 글꼴 모두 SIL Open Font License 1.1이다. 라이선스 원문을 `app/assets/fonts/licenses/OFL-*.txt`에 넣었고 앱에도 함께 들어간다(google/fonts 저장소의 `OFL.txt`).
- **출처**: Fontsource가 배포하는 굵기별 파일을 2026-11-14에 받았다(`cdn.jsdelivr.net/fontsource/fonts/<글꼴>@latest/<subset>-<굵기>-normal.ttf`). Inter Tight와 JetBrains Mono는 `latin` 부분집합, Noto Sans KR은 `korean` 부분집합이다. `@latest`로 받아서 **정확한 패키지 버전은 확인 필요**다. 파일은 위 해시로 고정된다.
- **범위**: 앱의 모든 문구가 이 글꼴들로 그려지는지 확인했다(`app/lib`의 문자열에 쓰인 글자가 모두 글꼴에 있음, 한글 음절 11,172자 전부 있음). 라틴 부분집합에 없는 기호(예: 화살표 ←)는 쓰지 않는다. 없는 글자가 나오면 Flutter 웹이 대체 글꼴을 외부에서 받으려 할 수 있다.
- Noto Sans KR의 OFL에는 Reserved Font Name 'Source' 조항이 있다. 부분집합 파일의 배포가 이 조항에 걸리는지는 **확인 필요**다(글꼴 이름을 'Source'로 쓰지는 않는다).

## 간격과 모양

- 8pt 그리드: 4 / 8 / 16 / 24 / 32 (`TSpace.x1`~`x5`).
- 화면 좌우 여백 20. 넓은 화면(웹)에서는 본문 너비를 560으로 제한하고 가운데에 둔다.
- 모서리 반경은 모두 0이다.
- 그림자와 그라데이션을 쓰지 않는다.

## 가독성 기준

| 기준 | 값 | 확인 방법 |
|---|---|---|
| 본문 글자 | 16 이상 | 테스트 |
| 보조 글자 | 13 이상 | 테스트 |
| 줄간격 | 본문·보조 1.5 | 테스트 |
| 대비 | 글자 4.5:1 이상, 조작 요소 테두리 3:1 이상 | 테스트(계산) |
| 터치 영역 | 높이 48 이상 | 테스트(버튼, 단계 행) |
| 글자 크기 확대 | 1.3배, 2배에서 넘침 없음 | 테스트(모든 화면, 360×640과 320×568) |

글자 크기 확대에 버티기 위한 규칙:

- 고정 높이를 쓰지 않는다. 최소 높이만 둔다.
- 모든 화면은 세로로 스크롤된다. 버튼도 스크롤 안에 둔다.
- 가로로 나란한 글자는 줄바꿈되게 한다. 이름과 값은 좌우가 아니라 위아래로 쌓는다.

## 상태 → 라벨·색

| 서버 응답 | 화면 | 라벨 | 색조 |
|---|---|---|---|
| `queued` | 분석 중 | 대기 중 | `muted` |
| `processing` | 분석 중 | 분석 중 | `muted` |
| `failed` | 분석 중(끝내지 못함) | 분석 실패 | `warning` |
| `cancelled` | 분석 중(끝내지 못함) | 취소됨 | `muted` |
| `finished` + `analysis_unavailable` | 영상 접근 불가 | 영상 접근 불가 | `warning` |
| `finished` + `out_of_scope` / `unsupported` / `insufficient_quality` | 분석 대상 아님 | 분석 대상 아님 | `muted` |
| `finished` + `assessed` + `verdict_label=suspicious_signals` | 결과 | 의심 신호 발견 | `accent` |
| `finished` + `assessed` + `verdict_label=low_suspicion` | 결과 | 의심 신호 낮음 | `neutral` |
| `finished` + 그 밖(`abstained`, 라벨 없는 `assessed`, 모르는 값) | 결과 | 판단 보류 | `warning` |

- 위에서부터 차례로 본다(`app/lib/view_state.dart`의 `resolveScreen`). 작업 종료, 분석 완료, 판정은 서로 다른 필드다.
- 발견·낮음은 서버가 준 `verdict_label`로만 정한다. 앱은 `overall_score`로 라벨을 만들지 않는다.
- **실제 서버 모드에서는 라벨이 와도 판단 보류로 보여 준다.** 검증된 결합 모델이 없기 때문이다. 발견·낮음 화면은 mock 모드에서만 나온다.

## 문구 규칙

- 진위를 확정하지 않는다. "가짜입니다", "진짜 영상입니다", "안전합니다"를 쓰지 않는다.
- 발견 화면: "이 결과는 조작을 확정하지 않습니다."
- 낮음 화면: "'의심 신호 낮음'은 진짜 영상이라는 뜻이 아닙니다."
- 보류·접근 불가·대상 아님 화면: "의심 신호가 있다고도 없다고도 판단하지 않았습니다."
- 원시 지표: "확률 아님". SyncNet: "진위를 가리는 모델이 아니라 동기화를 재는 보조 지표입니다."
- 분석 범위: "분석한 양이며 정확도나 신뢰도가 아닙니다."
- 원인 코드는 정해진 문구로만 바꾼다(`reasonText`). 모르는 코드는 설명을 꾸며 내지 않고 "이유가 기록되지 않았습니다"로 둔다.
- 결과 요약에 나오는 숫자는 분석 범위의 시간(분·초)뿐이다.

## 확인하지 않은 것

- 실제 노년층 사용자와의 가독성 검증.
- 화면 낭독기(VoiceOver, TalkBack)로 읽어 본 것. 의미 정보(`Semantics`)는 넣었지만 기기에서 듣지 않았다.
- iOS·Android 기기에서의 표시. 지금은 웹(Chrome)만 확인했다.
- 밝은 테마. 어두운 테마 하나뿐이다.
