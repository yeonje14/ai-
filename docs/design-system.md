# TRINITY 디자인 시스템

README §14.1 백로그 13번(P3-1). 처음 작성 2026-11-14, 같은 날 밝은 테마로 개정. 구현: `app/lib/design/`.

> 화면에 나오는 결과는 모두 가상 데이터다. 실제 모델이 연결되기 전까지 모든 화면 맨 위에 "모델 미연결 · 가상 데이터" 띠를 둔다.

## 원칙

1. **진위를 확정하는 것처럼 보이지 않는다.** 결과 요약은 "의심 신호 발견 / 의심 신호 낮음 / 판단 보류"와 "영상 접근 불가 / 분석 대상 아님"뿐이다. 숫자 점수와 퍼센트를 쓰지 않는다.
2. **"의심 신호 낮음"에 초록을 쓰지 않는다.** 초록은 안전·진짜로 읽힌다. 완전한 무채색을 쓰고, "진짜 영상이라는 뜻이 아니에요"라는 문구를 함께 둔다.
3. **색만으로 뜻을 전하지 않는다.** 상태에는 항상 글자 라벨과 아이콘이 있다.
4. **노년층이 읽을 수 있어야 한다.** 큰 글자, 높은 대비, 넓은 터치 영역, 시스템 글자 크기 확대 대응.
5. **없는 값은 없다고 말한다.** `null`은 "값 없음"으로 보여 준다. 0으로 바꾸지 않는다.
6. **차분하게 보인다.** 밝은 바탕, 둥근 모서리, 낮은 채도. 경고처럼 보이는 것은 상태 색 두 가지뿐이다.

### 대비 (WCAG 2.x 계산값)

상태 색이 글자·라벨로 놓이는 배경마다 계산했다. 기준은 4.5:1이다.

| 글자색 | 라벨 바탕 위 | 카드(`paper`) 위 | 화면 배경(`bg`) 위 |
|---|---|---|---|
| 밝은 `suspicious` `#B63A13` | 5.24:1 | 5.83:1 | 5.33:1 |
| 밝은 `warning` `#805B05` | 5.40:1 | 6.15:1 | 5.62:1 |
| 밝은 `low` `#2B2B2B` | 11.56:1 | 14.16:1 | 12.95:1 |
| 밝은 `muted` `#626A63` | 4.67:1 (`soft`) | 5.58:1 | 5.11:1 |
| 어두운 `suspicious` `#FF9671` | 6.28:1 | 7.26:1 | 8.29:1 |
| 어두운 `warning` `#F4D26D` | 8.40:1 | 10.53:1 | 12.02:1 |
| 어두운 `low` `#E6E6E6` | 10.12:1 | 12.40:1 | 14.16:1 |
| 어두운 `muted` `#AAB3AA` | 5.61:1 (`soft`) | 7.18:1 | 8.19:1 |

- 본문색 `ink`는 모든 바탕(안내 박스의 옅은 색 포함)에서 밝은 테마 12.5:1 이상, 어두운 테마 10.5:1 이상이다.
- 기본 버튼의 글자(`paper` on `ink`)는 밝은 테마 14.97:1, 어두운 테마 13.47:1이다.
- 조작 요소의 테두리 `controlLine`은 밝은 테마 3.49:1 이상, 어두운 테마 4.62:1 이상이다(기준 3:1).
- 참고: 이전 색은 흰 배경에서 `#FF3D00` 3.55:1, `#FACC15` 1.53:1로 기준에 못 미친다.
- `app/test/design_test.dart`가 두 테마의 이 조합을 모두 계산해 확인한다. 색을 바꾸면 테스트가 먼저 실패한다.

### 초록에 대한 규칙

- "의심 신호 낮음"의 글자와 바탕은 R=G=B인 무채색이다(테스트가 확인한다).
- 화면 전체의 회색(`bg`, `soft`, `ink`, `muted`)에는 시안대로 옅은 초록빛이 있다. 채도가 낮은 바탕색이며 상태를 뜻하지 않는다.
- 상태 색(`suspicious`, `warning`)과 그 바탕은 초록 계열이 아니다.

### 아이콘

Flutter에 들어 있는 Material 아이콘을 쓴다(새 의존성 없음, 쓰는 것만 빌드에 들어간다). 아이콘은 항상 글자와 함께 있고 화면 낭독기에서는 뺀다.

## 간격과 모양

- 8pt 그리드: 4 / 8 / 16 / 24 / 32 (`TSpace.x1`~`x5`). 화면 좌우 여백 20.
- 반경: 카드 14, 버튼·입력란 8, 라벨 6, 범위 막대 4, 웹 홈 입력창 32(캡슐).
- 본문 최대 너비 760, 웹 홈 입력창 680.
- 그림자와 그라데이션을 쓰지 않는다. 면은 색과 1px 선으로 구분한다.

## 배치

| 너비 | 배치 |
|---|---|
| 768 이하 | **앱 배치.** 모든 것을 세로로 쌓는다 |
| 768 초과 | **웹 배치.** 홈은 검색창 중심, 결과는 요청 상태를 오른쪽에, 단계 목록은 두 줄 |

- 768은 저장소 소유자가 정한 값이다.
- **앱 홈**: 상단 로고와 메뉴(영상 확인 / 이용 안내) → 작은 영문 머리글 → 왼쪽 정렬 두 줄 제목 → 짧은 설명 → 주소 입력 카드(입력란, 폭을 채우는 "분석 요청" 버튼) → 허가·업로드 안내 → 살펴보는 단서 세 가지.
- **웹 홈**: 맨 위 고지 띠 → 오른쪽 위 작은 "이용 안내" → 화면 가운데보다 조금 위에 큰 워드마크 → 한 줄 소개 → 폭 680의 캡슐 입력창(왼쪽 링크 아이콘) → 가운데에 "분석 요청"과 mock 전용 "예시로 둘러보기" → 작은 글씨 "허가된 영상만 확인합니다" → 접힌 "무엇을 분석하나요?". 입력창을 감싼 카드, 큰 메뉴, 영문 머리글, 원형 장식은 없다.
- 웹 홈의 배치는 검색 서비스의 첫 화면에서 흔한 구성을 따랐다. 다른 서비스의 로고 색이나 브랜드 요소는 쓰지 않았다.
- 웹의 홈이 아닌 화면에는 상단에 로고(처음으로)와 메뉴가 있다.

## 가독성 기준

| 기준 | 값 | 확인 방법 |
|---|---|---|
| 본문 글자 | 16 | 테스트 |
| 가장 작은 글자 | 13 | 테스트 |
| 줄간격 | 본문·보조 1.5 | 테스트 |
| 대비 | 글자 4.5:1 이상, 조작 요소 테두리 3:1 이상 | 테스트(두 테마 모두 계산) |
| 터치 영역 | 높이 48 이상 | 테스트(버튼, 글자 버튼, 단계 행, 접는 구역) |
| 글자 크기 확대 | 1.3배, 2배에서 넘침 없음 | 테스트(모든 화면, 너비 320·360·768·769·1280) |

글자 크기 확대에 버티기 위한 규칙:

- 고정 높이를 쓰지 않는다. 최소 높이만 둔다.
- 모든 화면은 세로로 스크롤된다. 버튼도 스크롤 안에 둔다.
- 가로로 나란한 것은 줄바꿈되게 한다(`Wrap`). 이름과 값은 위아래로 쌓는다.
- 상단 로고는 자리가 모자라면 줄어든다.

| 상단 줄 | `TrinityHeader` | 로고 + 메뉴, 또는 웹 홈의 작은 "이용 안내"만 |
| 기본 버튼 | `PrimaryButton` | 화면에서 가장 중요한 동작 하나. 본문색 바탕, 최소 높이 48 |
| 보조 버튼 | `SecondaryButton` | 흰 바탕과 테두리. 최소 높이 48 |
| 글자 버튼 | `TextLinkButton` | 밑줄 있는 글자. 뒤로 가기, 이용 안내 |
| 상태 라벨 | `StatusLabel` | 옅은 바탕 + 아이콘 + 글자. 색조는 `suspicious` / `warning` / `low` / `muted` |
| 단계 목록 행 | `StageRow` | 단계 이름 + "완료 / 진행 중 / 대기". 숫자와 %를 쓰지 않는다 |
| 분석 범위 카드 | `CoverageBar` | "어디까지 살펴봤나요?". 영상 길이 위에 분석한 구간. "분석한 양이며, 정확도나 신뢰도가 아닙니다"를 항상 함께 둔다. 길이를 모르면 구간을 그리지 않는다 |
| 축별 결과 행 | `AxisResultRow` | 이름, 설명, 상태, 지표(이름 위·값 아래). 원시 지표 이름에 "확률 아님"을 붙인다 |
| 안내 박스 | `InfoBox` | 색조의 옅은 바탕 위에 본문색 글자. 제목만 색조의 색이다 |
| 카드 | `Panel` | 흰 바탕, 1px 선, 반경 14 |
| 접는 구역 | `Disclosure` | 제목 줄을 누르면 펴진다 |

보조 위젯: `TrinityScaffold`(화면 틀), `TrinityNav`(처음으로·이용 안내 이동), `SectionTitle`, `Overline`, `KeyValue`.

## 상태 → 라벨·색

| 서버 응답 | 화면 | 라벨 | 색조 |
|---|---|---|---|
| `queued` | 분석 중 | 대기 중 | `muted` |
| `processing` | 분석 중 | 분석 중 | `muted` |
| `failed` | 분석 중(끝내지 못함) | 분석 실패 | `warning` |
| `cancelled` | 분석 중(끝내지 못함) | 취소됨 | `muted` |
| `finished` + `analysis_unavailable` | 결과 | 영상 접근 불가 | `warning` |
| `finished` + `out_of_scope` / `unsupported` / `insufficient_quality` | 결과 | 분석 대상 아님 | `muted` |
| `finished` + `assessed` + `verdict_label=suspicious_signals` | 결과 | 의심 신호 발견 | `suspicious` |
| `finished` + `assessed` + `verdict_label=low_suspicion` | 결과 | 의심 신호 낮음 | `low` |
| `finished` + 그 밖(`abstained`, 라벨 없는 `assessed`, 모르는 값) | 결과 | 판단 보류 | `warning` |

- 위에서부터 차례로 본다(`app/lib/view_state.dart`의 `resolveScreen`). 작업 종료, 분석 완료, 판정은 서로 다른 필드다.
- 결과 화면의 "이번 요청의 상태"가 작업·분석·판정을 따로 보여 준다. "작업이 끝났다고 진위가 확인된 것은 아니에요."
- 발견·낮음은 서버가 준 `verdict_label`로만 정한다. 앱은 `overall_score`로 라벨을 만들지 않는다.
- **실제 서버 모드에서는 라벨이 와도 판단 보류로 보여 준다.** 검증된 결합 모델이 없기 때문이다. 발견·낮음 화면과 "예시로 둘러보기"는 mock 모드에서만 나온다.

## 문구 규칙

- 진위를 확정하지 않는다. "가짜입니다", "진짜 영상입니다", "안전합니다"를 쓰지 않는다.
- 발견 화면: "이 결과는 조작을 확정하지 않습니다."
- 낮음 화면: "'의심 신호 낮음'은 진짜 영상이라는 뜻이 아니에요."
- 보류·접근 불가·대상 아님 화면: "의심 신호가 있다고도 없다고도 판단하지 않았습니다."
- 원시 지표: "확률 아님". SyncNet: "진위를 가리는 모델이 아니라 동기화를 재는 보조 지표입니다."
- 분석 범위: "분석한 양이며, 정확도나 신뢰도가 아닙니다."
- 원인 코드는 정해진 문구로만 바꾼다(`reasonText`). 모르는 코드는 설명을 꾸며 내지 않고 "이유가 기록되지 않았습니다"로 둔다. 서버 설명이 같은 원인 코드면 되풀이하지 않는다.
- 결과 요약에 나오는 숫자는 분석 범위의 시간뿐이다.
- 제목과 안내는 해요체, 사실 진술과 한계 고지는 합니다체를 쓴다.

## design-for-ai 플러그인 지침과의 관계

`design-for-ai` 4.2.0의 지침을 읽고 참고했다(자동 커밋과 검토 에이전트가 도는 `build` 흐름은 쓰지 않았고 `DESIGN.md`를 따로 만들지 않았다).

- 따른 것: 색을 역할 이름으로 부르는 토큰 단계, 터치 영역(지침의 최소 44보다 큰 48), 색만으로 뜻을 전하지 않기.
- **지침과 다른 결정 두 가지** (저장소 소유자의 지시를 따랐다):
  - 배치 전환 너비를 768로 고정했다. 지침은 기기 너비에 맞춘 고정 전환점보다 내용이 어색해지는 지점을 권한다.
  - 웹 홈을 가운데 정렬로 했다. 지침은 "모두 가운데 정렬"을 흔한 AI 생성 디자인의 특징으로 본다. 검색창 하나가 전부인 화면이라 그대로 뒀다.
- 지침의 색 도구(`palette.mjs`)와 검토 스크립트(`detect.mjs`)는 실행하지 않았다. 대비는 앱의 테스트로 계산했다.

## 확인하지 않은 것

- 실제 노년층 사용자와의 가독성 검증.
- 화면 낭독기(VoiceOver, TalkBack)로 읽어 본 것. 의미 정보(`Semantics`)는 넣었지만 기기에서 듣지 않았다.
- iOS·Android 기기에서의 표시. 웹(Chrome)과 테스트 렌더링만 확인했다.
- 어두운 테마를 브라우저에서 본 것. 테스트 렌더링으로만 봤다.
- 시안과 픽셀 단위로 견준 것. 배치와 색을 눈으로 견줬다.
