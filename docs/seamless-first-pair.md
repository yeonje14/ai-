2026-11-25 · `docs/seamless-pilot-plan.md` §3. 예약은 `docs/seamless-reservation.md`(커밋 `c6c67db`, 미디어 받기 전)를 따른다.
**MuseTalk 합성은 하지 않았다**(지도교수 확인 대기). 이 문서는 파일, 시간축, 얼굴 높이, Gate, 축별 결과까지만 다루고 여기서 멈춘다.

상세 결과 JSON은 Git 밖 `data/research/seamless/pilot/pilot-00/`에 있다.

- A·B의 영상 길이와 WAV 길이는 서로 같다(차이 0.000초).
- B의 WAV와 A의 MP4 자체 오디오의 상관은 0.015다. 각 WAV는 그 참가자 쪽 음성이고, MP4 자체 오디오는 같은 참가자의 WAV와 거의 같은 신호로 보인다.
- 계획서의 "전신 1080p" 가정과 달리, 이번 파일은 2160×3840 세로 영상이다. 다른 기관의 해상도는 확인하지 않았다.
- **사람 확인(2026-11-25, 사용자 원본 재생): 육안으로 뚜렷한 입·소리 어긋남 없음, 정밀 판정 불가.** 프레임 단위 어긋남은 이 확인으로 판단할 수 없다. 아래 SyncNet 오프셋은 보조 근거일 뿐이다.

## 3. 실제 조건 입력(MKV)

- 원본 MP4의 영상 스트림을 복사하고, **같은 참가자의 WAV 하나만** 오디오 트랙으로 넣은 MKV를 작업 폴더에 만들었다. MP4 자체 오디오는 넣지 않았고 재인코딩도 하지 않았다.
  - 확인 결과 영상 1개(h264, 시작 0.033초)와 오디오 1개(pcm_f32le, 시작 0.000초)다. 약 439MB이고 만드는 데 0.8–1.1초 걸렸다.
- 영상과 WAV의 시작 시각(0.033초 대 0초)은 그대로 두었다. 시간축을 옮기는 처리는 하지 않았다.
- **이 MKV는 첫 쌍 확인용이다.** 10쌍 단계에서는 실제 조건과 두 합성 조건을 **같은 최종 인코딩**(길이, 해상도, 프레임률, 소프트웨어 인코더 설정)으로 맞춘다. 실제만 무손실 PCM·원본 비트스트림이고 합성은 재인코딩된 상태로 비교하면, 클래스별 인코딩 차이가 결과에 섞인다(계획 §4, §5 "문제를 고쳐 재검").

## 4. Gate와 축별 결과

Worker(`server/jobs/worker.py`)와 같은 함수, 순서, 제한으로 돌렸다(`scripts/seamless_first_pair.py run`). 설정은 기본값이며 환경변수 재정의는 없다.
- 순서: Gate → WaveRep → MotionPhys → SyncNet
- Gate 제한은 `min(gate_timeout 120초, 작업 600초)`이다. Gate 뒤 작업 제한은 `min(1800, 180 + 20 × 적합 구간 초)`로 다시 정한다.
- 검증된 결합 묶음은 없다. 따라서 `overall_score`는 null이고 점수는 판정이 아니다.

**SyncNet 세부(A).**
- 2초 미만 구간 12개(17.6초)는 기존 규칙대로 제외했다.
- 남은 13개 구간 가운데 12개는 트랙 1개씩을 얻었다. 304.6–306.5초 구간 1개는 트랙이 없었다. 남은 구간 하나라도 트랙이 없으면 축 상태는 `tracking_failed`가 된다. 대표값 `lse_c`와 `lse_d`는 null이다.
- 트랙별 오프셋은 모두 **+4~+5프레임(25fps)**이었다. 본인 촬영 `A.MOV` 원본도 +4프레임이었다(`docs/syncnet-adapter.md` "A.MOV 실제 오프셋 진단"). 그래서 이 값만으로 정렬 오류를 판단하지 않는다.
- SyncNet은 동기화 보조 지표이고 진위 분류기가 아니다.

- 받은 원본(895MB)은 남은 파일럿 단계를 위해 보존한다. MKV를 포함한 작업 폴더는 삭제했다.
- **시도 기록(같은 표본 pilot#0).** 첫 번째 A 실행(약 22분)은 측정 스크립트의 결함 때문에 끝에서 멈췄다. 디스크 표본 스레드의 속성 이름이 `threading.Thread._stop`과 겹친 것이 원인이다. 그래서 결과 JSON이 남지 않았고, 남은 작업 폴더(419MB)는 손으로 지웠다. 수정하고 시험을 추가한 뒤 다시 실행한 결과가 위 표다. 모델·설정·입력은 바꾸지 않았다.

## 6. 관찰과 다음 결정에 필요한 것 (판단은 하지 않음)

- **원본 해상도와 처리 시간.** 2160×3840, 320초 영상에서 Gate가 제한 120초에 닿았다(A 117.6초, B 초과). MotionPhys도 300초 제한에 걸렸다. 10쌍으로 넓히기 전에 아래 가운데 무엇을 할지 정해야 한다. 지금은 어느 것도 하지 않았다.
  - 분석 구간을 잘라 짧게 만들기
  - 최종 인코딩 단계에서 해상도를 정하기
  - 측정 전용으로 Gate 제한을 늘리기
  - 단, 서비스 제한을 바꾸려면 §15.3 결정 기록이 필요하다.
- **얼굴 크기는 충분하다.** 얼굴 높이 약 500px는 기준 96px, WaveRep 504px 조건과 비교해 문제가 되지 않는다.
- **발화량 차이.** 얼굴 대상 A의 발화가 B보다 적다(공식 VAD 23% 대 61%). 이 쌍에서 적합 구간 68.7초는 A의 발화량에 묶여 있다.
- **사람의 원본 재생 확인:** 육안으로 뚜렷한 입·소리 어긋남 없음, 정밀 판정 불가.
