# MotionPhys 재구현 명세

README §14.1 백로그 10번(P2-1)의 앞부분. 작성일: 2026-11-14.

근거: He, Tan, Tan, Liu, Wan. *MotionPhys: Detecting AI-Generated Videos via Physical Consistency of Optical-Flow Trajectories.* arXiv:2608.20770v1 (2026-08-21). arXiv의 HTML 본문을 2026-11-14에 읽었다.

> **공개 코드가 없다.** 논문 본문만 보고 다시 구현했다. 논문은 식과 구조는 밝혔지만 숫자 설정은 거의 밝히지 않았다.

- **확인 필요**: 논문에 없거나 모호해서 확인하지 못한 것.
- **우리 선택**: 확인하지 못한 부분을 TRINITY가 정한 값. 모두 임시값이며 `research/motionphys/`의 코드에 그대로 있다.

## 1. 궤적 추출

| 단계 | 논문 | 확인 필요 | 우리 선택 |
|---|---|---|---|
| 프레임 표본 | 영상 전체에서 N = 48 프레임을 균등하게 뽑는다 | 영상 길이가 달라지면 프레임 간격이 달라지는데 이를 보정하는지. 48프레임보다 짧은 영상의 처리 | 입력이 "영상 + 시간 구간"이므로 **구간마다** 48프레임을 균등하게 뽑는다. 구간의 프레임이 48보다 적으면 있는 것을 모두 쓰고, 8보다 적으면 그 구간은 쓰지 않는다 |
| 처리 해상도 | 언급 없음 | 원본 해상도 그대로인지, 줄이는지 | 긴 변 640px로 줄인다(더 작으면 그대로). 좌표·속도·jerk의 단위는 이 해상도의 픽셀이다 |
| 점 초기화 | Shi–Tomasi 코너 검출과 규칙적인 격자 표본을 합친다. 코너는 무늬가 있는 영역, 격자는 매끈한 영역을 맡는다 | 코너 수, 품질 기준, 최소 거리, 격자 간격 | 코너 최대 200개(품질 0.01, 최소 거리 7px), 격자 간격 32px |
| 추적 | 피라미드 Lucas–Kanade로 프레임마다 추적해 위치를 갱신한다 | 창 크기, 피라미드 단계, 종료 조건 | 창 21×21, 3단계, 반복 30회 또는 0.01 |
| 추적 실패 | "성공적으로 추적된 위치"를 잇는다고만 한다. 유효 길이 T는 궤적마다 다를 수 있다(식 1) | 실패 판정 기준, 중간에 끊긴 궤적을 쓰는지, 최소 길이 | LK 상태값이 실패이거나, 역방향으로 다시 추적했을 때 1px 넘게 어긋나거나, 화면 밖으로 나가면 탈락. **클립 끝까지 살아남은 궤적만** 쓴다(T = L) |
| 시간 스케일 | L ∈ {8, 12, 24}. 스케일마다 표본 열을 길이 L의 클립으로 나누고 클립 안에서 추적한다 | 클립이 겹치는지, 클립마다 점을 다시 잡는지 | 겹치지 않게 나눈다(48프레임이면 6, 4, 2개). 클립의 첫 프레임에서 점을 다시 초기화한다. 남는 프레임은 버린다 |

여러 구간이 주어지면 구간마다 따로 추적하고, 궤적을 스케일별로 모아 한 번에 집계한다(우리 선택).

**구간 입력이 만드는 차이.** 논문은 영상 전체에서 48프레임을 뽑으므로 프레임 간격이 "영상 길이 / 48"이다. 우리는 구간 길이에 따라 간격이 달라진다. 10.4초 구간이면 약 0.22초(30fps 기준 6~7프레임에 한 장), 1.6초 구간이면 연속 프레임이다. 속도·가속도·jerk는 프레임 간격을 1로 놓고 계산하므로(식 3~8), **같은 움직임이라도 구간 길이에 따라 값이 달라진다.** 학습과 평가에서 구간 길이를 맞춰야 하는지는 데이터가 생긴 뒤에 확인한다(확인 필요).

## 2. 물리량 (논문 식 3~9)

궤적 τ = {p_t}, t = 1..T, p_t는 화면 위의 2차원 위치.

| 양 | 정의 (논문) | 길이 |
|---|---|---|
| 속도 | v_t = p_{t+1} − p_t (식 3) | T−1 |
| 가속도 | a_t = v_{t+1} − v_t (식 4) | T−2 |
| 곡률 | κ_t = \|v_t^x a_t^y − v_t^y a_t^x\| / (‖v_t‖³ + ε) (식 5) | T−2 |
| 각속도 | v̂_t = v_t / (‖v_t‖ + ε) (식 6), ω_t = arccos(clip(v̂_t · v̂_{t+1}, −1, 1)) (식 7). 단위는 rad/프레임 | T−2 |
| jerk | j_t = a_{t+1} − a_t = p_{t+3} − 3p_{t+2} + 3p_{t+1} − p_t (식 8), ρ_t = ‖j_t‖ (식 9) | T−3 |

- **확인 필요**: ε의 값. 논문은 "수치 안정을 위한 작은 상수"라고만 한다.
- **우리 선택**: ε = 1e-6.

식을 그대로 구현했을 때 생기는 성질(테스트로 고정했다):

- **정지한 점**: 곡률 0, jerk 0이지만 각속도는 π/2가 된다. v̂가 0벡터라 내적이 0이기 때문이다. 격자점이 정지한 배경에 놓이면 "90도씩 꺾이는 궤적"으로 기록된다.
- **아주 작은 움직임**: ‖v‖³이 작아져 곡률이 매우 커진다. 추적 잡음 수준(0.02px)의 움직임은 3px/프레임의 움직임보다 곡률 중앙값이 100배 이상 크다. 곡률 통계는 거의 움직이지 않는 점의 영향을 크게 받는다.
- **직선 운동**: ε 때문에 각속도가 정확히 0이 아니라 약 sqrt(4ε/‖v‖)이다(‖v‖ = 2.2px이면 0.0013 rad). 무시할 수 있는 크기다.
- **jerk의 잡음 증폭**: 위치에 표준편차 σ의 잡음이 있으면 jerk의 성분 분산은 20σ²이다(계수 1, 3, 3, 1의 제곱합). jerk 크기의 평균은 약 5.6σ, 같은 잡음이 속도에 주는 영향(약 1.77σ)의 √10배다.

논문이 정지한 점이나 작은 움직임을 걸러내는지는 **확인 필요**다. **우리 선택**: 논문에 걸러낸다는 말이 없으므로 특징 계산에는 유효 궤적을 모두 넣고, "움직인 궤적"의 수는 따로 센다(§5).

## 3. 통계 집계 (논문 식 10~19)

| 단계 | 정의 (논문) | 차원 |
|---|---|---|
| 궤적 수준 | 각 물리량의 값 열 q에 φ(q) = [평균, 표준편차, 최소, 최대, 왜도, 첨도, 중앙값, IQR] (식 10). 세 물리량을 이어 f = [φ(κ); φ(ω); φ(ρ)] (식 11) | 24 |
| 스케일 수준 | 스케일 L의 유효 궤적 M_L개의 f를 쌓고, 24개 차원마다 궤적 간 통계 ψ = [평균, 표준편차, 최소, 최대, 중앙값, Q25, Q75] (식 15)를 이어 붙인다 (식 16) | 168 |
| 영상 수준 | z = [z⁸; z¹²; z²⁴] (식 18) | 504 |

- **확인 필요**: 표준편차의 자유도, 왜도·첨도의 정의(편향 보정, 초과 첨도 여부), 백분위 보간 방식, 값이 모두 같은 열의 왜도·첨도.
- **우리 선택**: 표준편차는 모집단(ddof = 0). 왜도와 첨도는 편향 표본 적률로 계산하고 첨도는 초과 첨도(정규분포가 0). 분산이 0이면 왜도와 첨도를 0으로 둔다. 백분위는 선형 보간(NumPy 기본).
- 특징의 순서는 `스케일 → 물리량 → 궤적 통계 → 궤적 간 통계`이고 이름은 `L8.jerk.mean.median`처럼 붙인다(`kinematics.feature_names`). 논문은 순서를 식 (16), (18)의 연결 순서로만 정했다.
- 스케일 L = 8이면 궤적 하나에 곡률 6개, 각속도 6개, jerk 5개가 나온다. 8개 통계를 5~6개 값에서 계산하므로 왜도·첨도는 불안정하다(논문의 정의가 그렇다).

## 4. 분류기

- **논문**: 504차원 벡터를 가벼운 분류기에 넣는다. 기본은 LightGBM이고, 특정 분류기에 의존하지 않는다고 한다. 영상 단위의 판정이다.
- **확인 필요**: LightGBM 하이퍼파라미터, 특징 정규화 여부, 판정 임계값.
- **우리 선택**: LightGBM 기본값에 재현성 설정(고정 시드, 단일 스레드, deterministic)만 더했다. 정규화는 하지 않는다(트리 모델). 점수는 원시 margin으로 내고 확률로 바꾸지 않는다. 임계값은 `training.evaluation.run fit-threshold`가 dev 분할에서 정한다. **실제 학습은 하지 않았다**(DeepSpeak v2 승인 후).

## 5. 분석 가능 기준과 상태 (우리 선택)

논문에는 "분석할 수 없는 영상"에 대한 규칙이 없다. README §5.2에 따라 다음을 둔다. 값은 모두 임시값이고 개발 검증 데이터에서 정한 뒤 고정한다.

| 기준 | 임시값 | 결과 |
|---|---|---|
| 스케일마다 끝까지 추적된 궤적 수 | 20개 미만 | `status = insufficient_input`, `reason_code = tracking_failed` |
| 스케일마다 움직인 궤적 수(한 걸음 평균 이동 0.5px 이상) | 10개 미만 | `status = insufficient_input`, `reason_code = insufficient_motion` |
| 8프레임 이상인 구간 | 없음 | `status = insufficient_input`, `reason_code = segment_too_short` |

실패하면 특징은 `null`이다. 0으로 채우지 않는다. 결과에는 스케일별 유효 궤적 수, 움직인 궤적 수, 추적 성공률, 움직임 크기(한 걸음 평균 이동의 중앙값), 구간별 프레임 간격을 함께 싣는다.

## 6. 세 후보 (README §5.2)

세 후보는 같은 인터페이스를 쓴다: `extract.extract(video, segments, variant)` → 상태, 특징 벡터, 유효 궤적 수.

| 후보 | 내용 | 차원 | 논문과의 관계 |
|---|---|---|---|
| A `full` | §1~§3 그대로. 화면 전체 | 504 | 논문의 재구현(구간 입력은 다르다) |
| B `face_roi` | A와 같되 점을 **얼굴 박스 안에서만** 초기화한다. 박스는 클립 첫 프레임에서 MediaPipe Face Detector가 찾은 가장 큰 얼굴이고 사방으로 10% 넓힌다. 얼굴이 없는 클립은 건너뛴다 | 504 | 논문과 다른 조건. 논문에 없는 실험이다 |
| C `face_motion` | MediaPipe Face Landmarker의 얼굴 특징점을 궤적으로 본다. 세 영역(머리, 눈썹, 입술)마다 §2~§3을 적용해 504차원씩 만든다 | 1,512 | 프로젝트 임시 설계. 전부 우리 선택이다 |

후보 C의 세부(전부 우리 선택):

- 특징점: 머리는 얼굴 윤곽 36점, 눈썹은 좌우 20점, 입술은 40점. MediaPipe가 제공하는 연결 목록(`FACE_LANDMARKS_FACE_OVAL` 등)에서 번호를 얻는다(mediapipe 1.2.3 기준).
- 머리는 화면 좌표 그대로 쓴다(머리 전체의 움직임).
- 눈썹과 입술은 프레임마다 얼굴 윤곽의 중심을 빼고, 눈 사이 거리(양쪽 눈 바깥 꼬리)를 그 클립의 중앙값에 맞춰 크기를 보정한다. 머리의 이동과 카메라와의 거리 변화를 뺀 얼굴 안의 움직임이다. 머리의 회전은 빼지 않는다.
- 단위는 처리 해상도의 픽셀이다. 클립의 모든 프레임에서 얼굴이 잡혀야 그 클립을 쓴다.
- 움직임 기준은 머리 영역에만 적용한다.
- 특징점은 프레임마다 따로 추정되므로 추정 잡음이 그대로 궤적에 들어간다. §2의 잡음 증폭 때문에 곡률과 jerk가 특징점 검출기의 떨림을 재는 값이 될 수 있다(`docs/motionphys-spike.md`에 측정).

MediaPipe는 얼굴 위치와 특징점을 주는 도구이지 딥페이크 탐지기가 아니다.
