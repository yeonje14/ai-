# TRINITY 데이터 확보·검증 최종 계획서
## Seamless Interaction 자연 대화와 MuseTalk 립싱크 개발 파일럿

2026년 11월 24일 · 국립창원대학교 컴퓨터공학과 졸업작품 · MacBook Air M3, 메모리 16GB

**결정.** DeepSpeak 승인을 기다리는 동안, Meta Seamless Interaction의 실제 발화 영상과 같은 영상에서 만든 MuseTalk 립싱크 합성본으로 개발 파일럿을 진행한다. 미디어를 열기 전에 평가 후보를 예약한다. 예약한 파일럿 대화 1쌍으로 다운로드·시간 정렬·얼굴 품질을 확인하고, 첫 쌍을 포함한 총 10쌍에서 두 합성 조건을 비교한다. 주 학습 데이터 교체와 대규모 생성은 파일럿 보고서를 근거로 별도 결정한다.

**현재 확인한 범위.** 공식 파일 인덱스, 저장소의 분할 코드, 오탐률 상한 계산을 확인했다. 내부 평가 200쌍과 개발 검증 100쌍은 예약 목표다. 실제 예약 목록, 미디어 품질, MuseTalk MLX의 M3 처리량과 모델 성능은 미검증이다.

### 1. 데이터와 용도

| 자료 | 사용할 시점과 용도 |
|---|---|
| Seamless Interaction · naturalistic | 공식 train에서 TRINITY 내부 분할을 만들고 파일럿 원본을 고른다. 공식 dev·test는 개발 중 보존하고 별도로 보고한다. |
| MuseTalk 1.5 MLX | 파일럿 생성기. 포트·가중치·의존성 버전과 이용 조건을 기록한다. 파일럿 결과의 적용 범위는 이 립싱크 조건이다. |
| HiDF·LipSync-A | 다른 촬영 원천·조작 방식의 보조 평가 후보. 각 그룹의 개발용 또는 평가용 역할을 사용 전에 고정한다. |
| MAVOS-DD·TalkingHeadBench | 기존 설계의 최종 외부 평가 전용. MAVOS-DD open-set model 2,160개는 잠금을 유지한다. TalkingHeadBench는 원본 권리와 계보 확인 후 사용한다. |
| DeepSpeak·BabelFake | DeepSpeak는 기존 주 학습 후보로 승인 대기 중이다. BabelFake는 기관 확인과 연구용 이용 계약이 필요한 대체 후보다. 확보하면 사용 전에 역할을 정한다. |
| 동의받은 자체 촬영분 | 한국어 사례와 공개 시연에 사용한다. DFDC 등 대용량 보조 자료는 확대 단계에서 비용·이용 조건을 확인한다. |

Seamless의 배포 조건은 CC BY-NC 4.0이다. 연구 기록에 출처·버전·변경 내용을 표시한다. 참가자 합성본은 내부 실험에 사용하고 발표 시연은 동의받은 자체 영상으로 구성한다. **합성 시작 관문:** 분할 예약, 첫 쌍 다운로드, 실제 영상의 Gate·축 실행은 바로 할 수 있다. 참가자 얼굴로 MuseTalk 합성을 만드는 일은 지도교수에게 캡스톤의 비상업 이용 범위와 학교 절차를 확인받은 뒤에 시작한다. [Meta 데이터 카드](https://huggingface.co/datasets/facebook/seamless-interaction) · [BabelFake 접근 조건, 부록 A.1](https://arxiv.org/html/2610.06339v1)

### 2. 미디어를 열기 전 분할 예약

| 공식 naturalistic 분할 | 인덱스의 대화 수 | 기존 키 순서로 실제 고른 비중복 쌍 | 역할 |
|---|---:|---:|---|
| train | 45,239 | 1,130 | 전체 대화로 돌아가 누수 검사와 새 표집을 수행 |
| dev | 748 | 40 | 보조 확인용으로 보존 |
| test | 823 | 53 | 독립 보고용으로 보존. P 코드 113개 기준 이론상 최대 56쌍 |

위 수치는 영상 품질 검사 전의 파일 목록 집계다. 1,130은 한 가지 선택 순서의 결과다. 표집을 여기서 시작하면 앞선 선택 편향이 남는다. [Meta 공식 인덱스](https://github.com/facebookresearch/seamless_interaction/blob/main/assets/filelist.csv) · 기준 Git blob `e759e6d00f152a4833df2b985de842ab642812cd`

1. **후보 구성.** 공식 train의 45,239개 대화에서 촬영기관·세션·interaction을 기준으로 A·B 양쪽 파일 ID가 대응되는 후보를 만든다. 파일 ID 누락·중복, 쌍 관계 충돌 등 메타데이터로 미리 알 수 있는 제외 사유와 건수를 남긴다.
2. **누수 검사.** 참가자 두 명, 원본 세션·녹화, 영상·음성 공여자 및 재사용 관계를 연결해 한 분할에 묶는다. P 코드만 대조하면 train과 dev 사이에 17개, train과 test 사이에 32개가 겹쳤다. 촬영기관까지 포함하면 각각 0개였다. 이는 식별자 교집합이다. 메타데이터로 신원을 구별할 수 없는 충돌은 예약 후보에서 제외한다. 기관·세션·파생 관계를 반영한 뒤 실제 독립 그룹 수를 다시 센다.
3. **층화 예약.** 적격 후보의 촬영기관별 비율을 기준으로 목표 수를 배분한다. 사용할 시드와 추출·반올림·부족 시 처리 규칙을 먼저 기록한다. 기관 안에서는 무작위 순서로 보되, 한 번 쓴 참가자나 연결 그룹을 다른 몫에 다시 쓰지 않는다. 목표는 **내부 test 200쌍, 내부 dev 100쌍, 파일럿 10쌍**이다. 나머지가 내부 학습 후보다. 실제로 확보된 수와 기관별 구성을 보고하며 목표 부족을 이유로 누수 기준을 완화하지 않는다.
4. **예약 고정.** 상세 ID 목록은 Git 밖 연구 데이터 경로(`data/research/seamless/reservation/`)에 저장한다. 재현용 소스 버전, 시드, 표집 규칙, 역할별 건수, 정렬된 예약 파일의 SHA-256은 **저장소에 커밋**한다(`docs/seamless-reservation.md`). 커밋 시각이 "결과를 보기 전에 예약했다"는 증거가 된다. 파일럿 10쌍은 이후 평가에서 제외한다. 공식 dev·test와 내부 test의 미디어는 개발 중 열지 않는다.
5. **예약 보존 검사.** 저장소의 현행 어댑터는 공식 train을 다시 train/dev로 나눈다. 내부 분할 적용은 DESIGN §15.3 결정 6에 먼저 제안한다. 승인된 경로로 최종 manifest를 생성한 뒤 예약표와 역할을 행 단위로 대조한다. 내부 train에 들어간 dev/test 그룹 0개, 분할 간 참가자·원본·공여자 중복 0개, 파생본의 부모 분할 상속을 확인한다. 불일치하면 학습 전에 바로잡는다.

### 3. 첫 대화 한 쌍

예약한 파일럿 첫 쌍을 공식 S3 경로에서 ID로 지정해 받는다. 공식 안내의 두 참가자 자료는 약 200MB다. 한 경로의 DNS 오류는 접근 거절과 구분하고, 동일한 ID의 공식 배포 경로를 확인한다. [공식 다운로드 안내](https://github.com/facebookresearch/seamless_interaction)

- **파일과 시간축.** 양쪽 MP4·WAV·VAD의 대응, 해시, 디코딩, 선택 오디오 트랙, 시작 시각과 길이를 기록한다. 원본을 재생해 입 모양과 음성이 일치하는지 확인한다. Meta가 밝힌 약 10% 오류는 수작업 대화 구간·프롬프트 주석에 관한 수치다.
- **영상 적합성.** 전신 1080p 영상에서 실제 발화자의 얼굴 높이와 추적 구간을 잰다. 기존 Gate를 그대로 적용하고, WaveRep의 원본 짧은 변 504px 조건과 SyncNet의 유효 트랙을 각각 확인한다. 축별 실패 상태와 보류 이유를 남기며 실패 점수는 `null`로 둔다.
- **생성 및 자원.** 첫 쌍에서 아래 세 조건을 만들고 M3에서 소요 시간과 최대 디스크 점유량을 잰다. 동일 파일 재시도는 같은 표본 ID에 기록한다. 계보·음성 대응 오류는 확장 전에 수정하며, 실패한 대화도 예약 분모에 남긴다.

### 4. 총 10쌍에서 비교할 조건

얼굴 대상 A는 결과를 보기 전에 정한다. 같은 A 영상 구간을 세 조건에 공통으로 쓰고, 구동 발화는 길이를 맞춘다.

| 조건 | 영상과 음성 | 비교 목적 |
|---|---|---|
| 실제 | A의 원본 영상 + 같은 장면의 A 음성 | 원본에서 Gate와 각 축이 처리하는 구간 확인 |
| 같은 화자 합성 | 같은 A 영상 + A의 다른 발화로 MuseTalk 합성 | 화자를 유지한 립싱크 조작에서 출력 변화 확인 |
| 상대 화자 합성 | 같은 A 영상 + 대화 상대 B의 발화로 MuseTalk 합성 | 구동 음성이 바뀔 때 출력·처리 가능 비율의 변화 확인 |

모두 성공하면 **실제 10개, 합성 20개, 독립 대화 10개**다. 두 합성 조건에는 발화 내용과 음질 차이도 섞이므로 조건 간 차이를 화자 효과 하나로 귀속하지 않는다. 영상·음성 구간과 정렬을 보존하고, 최종 길이·해상도·프레임률·소프트웨어 인코딩 조건을 맞춘다. 음성만 앞당기는 무음 제거와 WaveRep 기준을 채우기 위한 확대는 사용하지 않는다. 합성기에 의한 추가 재인코딩과 얼굴 경계·흐림을 기록한다.

**예약 후 실패 규칙.** 입력 누락·디코딩 오류·발화 부족·Gate 거부·생성 오류·축별 보류를 서로 구분한다. 조건 하나가 실패해도 나머지 조건과 축은 가능한 범위에서 처리한다. 실패한 쌍을 몰래 교체하거나 SyncNet 출력에 따라 실제 영상을 제외하지 않는다. 표에는 계획 수, 실제 시도 수, 성공·보류·실패 수를 모두 남긴다. 보완 표본을 별도로 조사하면 원래 분모와 분리해 표시한다.

### 5. 10쌍 종료 후 확대 결정

| 판단 | 근거와 다음 행동 |
|---|---|
| 확대 제안 | 같은 원본에서 두 합성 조건을 재현했고, 예약과 실제 분할을 대조할 수 있으며, 입력·생성 실패 원인과 처리 비용이 설명된다. 쌍당 시간과 저장량으로 가능한 규모를 산정한 후 결정 6 변경을 제안한다. 조작 방식 일반화를 검증하려면 추가 생성기를 한 종류씩 도입한다. |
| 문제를 고쳐 재검 | 오디오 짝 오류·시간축 변경·클래스별 인코딩 차이·분할 누수가 발견되면 해당 단계부터 수정하고 같은 개발 표본으로 재검한다. |
| 용도 축소 | 얼굴 크기나 생성 비용 때문에 사용 범위가 좁으면 적합한 축·조건만 보고한다. 합성이 어려우면 Seamless는 실제 영상 처리 시험에 쓰고, HiDF·LipSync-A 입력 파일럿으로 전환한다. |

**파일럿 산출물**은 분할 감사표, 조건별 실행·보류 건수, 축별 입력 품질과 처리 시간, M3 최대 디스크 점유량, 확대 판단 한 쪽이다. 검토 당시 여유 공간은 약 30–31GiB였다. 한 쌍씩 처리하고 해시·절단 좌표·버전과 산출물 확인 후 재생성 가능한 임시 파일을 정리한다. 10쌍으로 탐지 정확도나 완료 일정을 확정하지 않는다.

### 6. 확대가 결정된 뒤의 성능 평가

내부 train으로 학습하고 내부 dev에서 후보·전처리·목표 영상 오탐률(FPR) 5%의 임계값을 고정한다. 고정 후 내부 test를 한 번 평가한다. 공식 Seamless dev/test는 출처를 표시해 보조 결과로 별도 보고한다. MAVOS-DD open-set의 Sonic·HiFiFace·Roop 직접 일치 생성기는 학습·개발에서 제외한다. 외부 점수로 모델을 다시 선택하지 않는다.

점수가 나온 실제 영상의 FPR과 그 영상들이 속한 독립 그룹 수 n을 사용한다. 저장소 방식은 유효 오탐 수 k = n × 영상 FPR에 소수를 허용한다. **그룹 bootstrap 95% 상한과 CP 방식 95% 상한 중 큰 값이 10% 이하**여야 FPR 관문을 통과한다. 판정 제공 비율과 보류 사유를 같이 보고한다.

| 판정된 독립 실제 그룹 n | 영상 FPR 예시 | 유효 k | CP 방식 상한 |
|---:|---:|---:|---:|
| 53 | 0% | 0 | 6.72% |
| 53 | 5% | 2.65 | 14.74% |
| 150 | 5% | 7.5 | 9.81% |
| 200 | 5% | 10 | 9.00% |

공식 test에서도 관측 오탐률이 충분히 낮으면 관문을 통과할 수 있다. 내부 test 200쌍을 예약하는 이유는 5% 부근의 오탐률을 더 많은 그룹에서 평가하기 위해서다. 실제로 점수가 나온 그룹이 줄면 분모와 상한을 다시 계산한다. 결합 모델은 현행 채택 규칙에 따라 WaveRep과 단일 최강 후보 모두와 비교한다. SyncNet은 동기화 보조 지표이며 검증된 결합 모델이 없을 때 전체 점수는 `null`이다. 결과의 적용 범위는 평가한 촬영 환경·조작 유형에 한정한다.

### 8. DeepSpeak 승인 시 규칙 (지금 고정)

승인 시점에 따라 역할을 정한다. 승인된 뒤에 정하면 그때까지 본 결과에 맞춰 고르는 셈이 되므로, 규칙은 지금 정해 둔다.

| 승인 시점 | DeepSpeak의 역할 |
|---|---|
| 내부 dev 임계값 고정 전 | 주 학습에 합류(기존 결정 6으로 복귀). Seamless는 진짜 영상 보강과 교차 평가에 쓴다. |
| 임계값 고정 뒤, 내부 test 열람 전 | 학습에 넣으려면 dev부터 다시 한다. 시간이 없으면 추가 독립 평가로만 쓴다. |
| 내부 test 열람 뒤 | 추가 독립 평가로만 쓴다. 재학습하지 않는다. |

- 어느 경우든 Seamless 내부 test 예약은 바꾸지 않는다.
- 승인되면 성능을 보기 전에 다음을 한다: test 진짜 그룹 수 세기, Sonic·HiFiFace·Roop 직접 일치 생성기 확인·제외, Seamless와의 인물 중복 확인, 역할을 하나로 정해 §15.3에 날짜와 함께 기록.
- DeepSpeak 어댑터 설정(`configs/datasets/deepspeak_v2.json`)이 이미 있어 코드 변경은 1등급이다. 실제 행으로 필드를 확인한 뒤 붙인다.

### 9. 설계 결정과 교수 보고 문안

**DESIGN §15.3 결정 6 변경 제안.** Seamless Interaction 공식 naturalistic train에서 참가자·원본·공여자 계보를 검사한 뒤 내부 평가 및 개발 검증 후보를 사전 예약한다. 별도 개발 10쌍에서 MuseTalk 립싱크 입력 적합성을 확인한다. DeepSpeak 승인 상태와 독립적으로 파일럿을 수행하고 주 학습 자료 교체는 실측 후 별도 결정한다. 기존 최종 외부 평가의 잠금과 용도를 유지한다.

**지도교수께 설명할 문구**

> DeepSpeak 승인 대기 중에도 개발을 진행할 수 있도록 Meta의 자연 대화 영상을 후보로 선정했습니다. 공개 파일 목록에서 참가자 ID가 겹치지 않는 train 대화 1,130쌍을 한 가지 선택 방식으로 확인했습니다. 실제 표집은 전체 train 목록에서 다시 진행하고, 모델 개발 전에 내부 평가 후보를 따로 예약할 계획입니다. 먼저 대화 한 쌍의 입력 품질을 확인한 뒤 총 10쌍에서 같은 화자의 다른 발화와 대화 상대의 발화를 사용한 립싱크를 비교하겠습니다. 이 단계에서는 처리 가능 범위와 비용을 측정하고, 정식 학습 및 성능 평가는 그 결과를 보고 결정하겠습니다.
