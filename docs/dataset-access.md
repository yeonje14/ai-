## MAVOS-DD

- 위치: `unibuc-cs/MAVOS-DD` (Hugging Face) · 논문 arXiv:2505.11109v2 · 코드 `CroitoruAlin/MAVOS-DD` (GitHub)
- **역할:** 최종 외부 평가(처음 보는 생성기). **open-set model 테스트 분할**만 쓴다. 학습·튜닝·임계값 결정에 쓰지 않는다. MAVOS-DD의 학습·검증 분할은 쓰지 않는다 (README §6.1, §13.1, §15.3 결정 6, 2026-11-13 변경).
- **접근 상태:** 접근이 승인됐다(2026-11-13, 저장소 소유자가 양식에 동의). **메타데이터 파일만 받았다**(`data/research/mavos-dd/`, Git 제외, 약 8.5 MB). 영상 파일은 받지 않았다.

### 일부만 받는 방법

- 파일이 폴더별 개별 mp4라서 폴더(언어·생성기) 단위 또는 파일 단위로 받을 수 있다.
  - 폴더 단위: `hf download unibuc-cs/MAVOS-DD --repo-type dataset --include "english/sonic/*" --local-dir data/research/mavos-dd`
  - 메타데이터만: `hf download unibuc-cs/MAVOS-DD data-00000-of-00001.arrow dataset_info.json state.json dataset.py metadata_generation.py README.md --repo-type dataset --local-dir data/research/mavos-dd` (2026-11-13에 실행해 확인. `--include "*.arrow"` 방식은 arrow 파일을 받지 못했다)
  - 표본만: 표본 목록의 경로를 하나씩 `hf download unibuc-cs/MAVOS-DD <경로> --repo-type dataset --local-dir data/research/mavos-dd`
- 폴더 단위와 표본 단위 명령은 **이 데이터셋에서 실행해 보지 않았다(미검증).** 접근 양식 동의와 로그인이 먼저 필요하다.
- 받는 위치는 `data/research/mavos-dd/`(Git 제외)다. 전체(308 GB)를 받지 않는다.
- 접근 제한을 피하는 다른 경로(제3자가 다시 올린 사본 등)로 받지 않는다.

### 해석할 때의 주의

1. **"처음 보는 생성기"의 기준.** MAVOS-DD의 open-set은 MAVOS-DD 학습 분할 기준이다. TRINITY는 DeepSpeak v2로 학습하므로, DeepSpeak v2에 같은 생성기가 있는지 확인한 뒤에만 그 생성기를 "처음 보는 생성기"라고 부른다. in-domain 부분과 추가 생성기 부분은 나눠서 보고한다.
2. **유통본이 아니다.** 진짜 영상은 YouTube에서 왔지만 가짜 영상은 연구진이 만든 것이다. 실제 SNS에서 유통된 조작 영상에 대한 평가를 대신하지 못한다. 결과 보고에 이 한계를 적는다.
3. **음성만 바꾼 가짜.** 음성 변환(VC) 영상은 화면이 진짜다. 영상 기반 축(WaveRep, MotionPhys)이 잡지 못할 수 있다. 생성 방식별로 나눠 보고한다.

| **전체** | | 4,964 / 21.6 | 11,418 / 27.0 | 6,175 / 27.7 | 4,641 / 12.7 | 8,901 / 31.7 | 7,860 / 34.7 | 43,959 / 155.3 |

- 메타데이터 필드: `video_path`, `label`, `split`, `open_set_model`, `open_set_language`, `language`, `generative_method`, `audio_generative_method`, `audio_fake`, `video_fake`.
- `freevc`·`knnvc` 폴더는 화면이 진짜이고 음성만 바꾼 영상이다(`video_fake=False`, `audio_fake=True`, `label=fake`). 5,958개로 가짜의 21%다.
- 영상 생성기 폴더 안에도 음성까지 바꾼 영상이 섞여 있다(`audio_fake=True`): `echomimic` 1,110, `liveportrait` 766, `memo` 346, `sonic` 1,123, `hififace` 980, `roop` 347개.
- 진짜 "추가분" 10,362개는 처음 보는 생성기의 가짜와 함께 테스트에만 들어가는 진짜 영상이다. 아랍어·루마니아어에는 없다.
- **원본 영상 묶음(추정).** 파일 이름에서 YouTube 영상 ID로 보이는 11자 문자열을 뽑아 같은 원본에서 나온 클립을 묶었다. 이름 규칙은 문서화되어 있지 않아 **파일 이름에서 추정한 것**이다. 이 분할의 43,959개 중 37,894개(86%)가 1,495개 원본으로 묶였다(원본당 중앙값 15개, 최대 389개). 514개는 Common Voice 음성 ID만 있고, 5,551개는 식별자가 없다(UUID 이름 등. 주로 `sonic`, `echomimic`, `hififace`, `liveportrait`).
- **MAVOS-DD의 분할은 원본 단위가 아니다.** in-domain 테스트는 파일 단위 무작위 분할이라(`metadata_generation.py`), 이 분할에 나오는 원본 1,495개 중 886개가 MAVOS-DD의 학습·검증 분할에도 나온다. TRINITY는 MAVOS-DD로 학습하지 않으므로 누수는 아니다. 다만 같은 원본의 클립끼리는 독립이 아니므로 신뢰구간은 원본 묶음 단위로 계산한다.

### 표본 추출 규칙 (결과를 보기 전에 고정)

2026-11-13에 정했다. open-set model 분할 전체를 받지 않고 표본으로 평가할 경우에 적용한다. **어떤 영상도 받거나 모델에 넣기 전에 정한 규칙이다.** 숫자(★)는 메타데이터 집계를 본 뒤 제안하고 저장소 소유자의 승인을 받아 이 절에 적는다. 숫자를 적은 뒤에 영상을 받는다.

| 항목 | 규칙 | 값 |
|---|---|---|
| 모집단 | 분할 메타데이터가 open-set model 테스트로 표시한 영상 전부. 다른 분할의 영상은 넣지 않는다 | – |
| 층 | 가짜: 생성기 × 언어. 진짜: 언어. 생성기는 메타데이터의 라벨을 따른다(음성 변환 조합의 처리는 라벨 확인 후 이 표에 적는다) | – |
| 생성기당 상한 | 생성기 하나에서 뽑는 가짜 영상 수의 상한. 그 생성기의 언어 층들에 같은 수로 나눈다 | ★ 미정 |
| 층이 모자랄 때 | 층의 영상 수가 배정 수보다 적으면 있는 만큼만 쓴다. 남는 수를 다른 층으로 옮기지 않는다. 부족분을 기록한다 | – |
| 진짜·가짜 비율 | 진짜 표본 수는 가짜 표본 총수에 비율을 곱해 정하고 언어 층에 같은 수로 나눈다 | ★ 미정 |
| 추출 방법 | 층마다 파일 경로를 사전순으로 정렬한 뒤, 고정 시드로 초기화한 `random.Random(시드)`로 층 순서(사전순)대로 `sample`한다. 비복원 추출 | – |
| 시드 | 한 번 정하면 바꾸지 않는다 | ★ 미정 |
| 표본 목록 | 뽑은 경로·층·시드를 manifest 파일로 저장하고 sha256을 이 문서에 적는다. manifest는 메타데이터만으로 만든다 | ★ 미정 |

지키는 것:

- 표본을 뽑은 뒤 결과를 보고 규칙, 숫자, 시드를 바꾸지 않는다. 바꾸면 그 결과를 독립적인 최종 평가라고 부르지 않는다(README §6.3).
- Gate에서 걸러지거나 추론에 실패한 영상을 다른 영상으로 바꿔 넣지 않는다. 보류·실패로 세고 판정 제공 비율과 함께 보고한다(README §13.1 선택적 분류).
- 표본으로 얻은 결과에는 표본 수와 추출 규칙을 함께 적는다. 층별 추출 비율이 다르므로 전체 분할의 성능 추정치로 쓸 때는 층별로 보고하거나 가중치를 밝힌다.
- 같은 원본 영상에서 나온 클립을 묶는 그룹 정보가 있으면 신뢰구간 계산에 쓴다. 표본 추출 단위를 그룹으로 바꿀지는 메타데이터를 본 뒤 숫자와 함께 제안한다.

## Deepfake-Eval-2024

- 위치: `nuriachandra/Deepfake-Eval-2024` (Hugging Face)
- **역할:** 실전 유통본 평가. **접근이 승인되면 최종 외부 평가에 추가한다**(README §15.3 결정 6, 2026-11-13 변경). 평가 전용이며 학습·튜닝·임계값 결정에 쓰지 않는다 (AGENTS.md, README §6.1). 반복적인 모델 수정 피드백에도 쓰지 않는다.
- **접근 상태:** Hugging Face에서 접근을 요청했다. 기관 이메일과 관련 작업 링크를 제출했다. 2026-11-13 기준 **거절됐다**(저장소 소유자 확인). 신청 날짜, 거절 통보 날짜, 거절 사유: **확인 필요.**
- **거절의 영향:** 이 데이터셋을 받을 수 없으므로 최종 외부 실전 평가(README §6.1·§13.1, 백로그 15번)에 쓸 자료가 지금은 없다. 다른 경로(미러, 제3자 사본)로 받지 않는다. 재신청이 가능한지는 **확인 필요**(양식 안내에는 제출 후 수정할 수 없다고만 적혀 있다).
- **결정 (2026-11-13, README §15.3 결정 6 변경):** 최종 외부 평가는 MAVOS-DD open-set model 분할과 TalkingHeadBench로 대체한다. Deepfake-Eval-2024는 재신청을 검토하고, 승인되면 실전 유통본 평가로 추가한다. 실제 SNS 유통본으로 평가하지 못하면 결과 보고에 그 한계를 명시한다.

| 확인된 것 | 근거 |
|---|---|
| 접근 제한이 있고 수동 승인 방식이다 (`gated: manual`) | HF 메타데이터 |
| 신청 양식 항목: 이름, 소속, 기관 이메일, 국가, 날짜, 사용 목적, 딥페이크 탐지 또는 관련 분야 작업을 보여 주는 검증 가능한 링크 | HF 메타데이터 |
| 양식 안내: 불완전하거나 질문에 직접 답하지 않은 응답은 거절되며, 제출 후 수정할 수 없다 | HF 메타데이터 |
| 이용 조건: **평가에만** 쓸 수 있다. 학습에 쓰는 것은 이용 조건 위반이다 | HF 메타데이터 (Terms of Use) |
| 이용 조건: 개인·기관·사회에 해를 줄 수 있는 기술의 개발·개선에 쓰지 않는다 | HF 메타데이터 (Terms of Use) |
| 라이선스 태그는 `cc-by-sa-4.0`이다. 상업적 이용의 적법성은 사용자가 직접 확인해야 한다 | HF 메타데이터 |

데이터셋의 "평가 전용" 조건은 TRINITY의 규칙(최종 평가 전용)과 같은 방향이다.

| 확인 필요 | 비고 |
|---|---|
| 거절 사유, 거절 통보 날짜, 재신청 가능 여부 | 통보 내용을 저장소 소유자가 알려 주면 반영. 양식 안내에는 제출 후 수정할 수 없다고만 적혀 있다 |
| 임계값 결정·확률 보정이 "평가"에 포함되는지에 대한 게시자 측 해석 | TRINITY는 어느 쪽이든 쓰지 않는다 |
| CC-BY-SA-4.0 아래에서 결과·파생물을 공개할 때의 표기와 동일조건 의무 범위 | 결과 보고 전 확인 |
| 수집된 원 영상(제3자 콘텐츠)의 권리 관계와 보관·삭제 조건 | 확인하지 않음 |
| 영상 중 "말하는 사람 한 명"이라는 TRINITY 분석 범위에 맞는 표본 수 | 접근이 거절돼 지금은 확인할 수 없다 |
| README §6.5의 "구체적 신청 기한" | 메타데이터에서 기한 정보는 찾지 못했다 |

## TalkingHeadBench

- 위치: `luchaoqi/TalkingHeadBench` (Hugging Face)
- **역할:** 최종 외부 평가(토킹헤드 생성 방식 일반화). 별도로 허용된 학습 분할은 추후 선택한다. 학습에 쓰면 그 부분은 더 이상 독립적인 외부 평가 자료가 아니라고 명시한다 (README §6.1).
- **접근 상태:** 접근 방법 **확인 필요.** 신청하지 않았고 파일을 받지 않았다.

| 확인된 것 | 근거 |
|---|---|
| HF 메타데이터상 접근 제한 표시가 없다 (`gated: false`) | HF 메타데이터 |
| 라이선스 태그는 `mit`이다 | HF 메타데이터 |

| 확인 필요 | 비고 |
|---|---|
| 실제 다운로드 절차와 별도 동의·양식이 있는지 | 메타데이터에 제한 표시가 없다는 것만 봤다. 데이터셋 카드 본문은 읽지 않았다 |
| `mit` 태그가 영상 데이터 전체에 적용되는지, 상위(원본) 영상의 권리는 어떤지 | README §6.1의 "상위 영상 권리" 항목 |
| 제공 분할의 구성 (학습/평가 구분, 생성 방식별 표본 수) | README §6.1 |
| 인물·원본 계보 정보 제공 여부, DeepSpeak와 인물·원본이 겹치는지 | 누수 검사에 필요 |
