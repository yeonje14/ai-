# Flutter 웹 디자인 개편 계획 — **승인 대기, 코드 변경 없음**

> 근거: 사용자 지시(2026-11-26), 제품 절대 규칙(AGENTS.md 맨 위), `docs/design-system.md`.
> 참고 이미지 `data/design-ref/reference.png`(Git 제외)에서는 분위기만 가져온다. 배치·그림·글자는 베끼지 않는다.
> 참고 이미지에 있는 숫자 카드("98%", "4.2M" 같은 것)는 규칙 3에 따라 쓰지 않는다.

## 0. 지키는 것

- **규칙 1(입력):** 입력 화면은 링크 붙여넣기 칸 하나와 붙여넣기 버튼이다. 파일 선택은 없다.
- **규칙 3(결과)**
  - 숫자 카드로 결론을 보여주지 않는다.
  - 결과 화면은 증거 중심이다: 어느 구간에서, 어떤 신호가, 진짜 영상 범위와 비교해 어떠한지.
  - 진짜 영상 범위는 4단계에서 만든다. 지금은 그 자리에 "비교 기준 준비 중 → 판단 보류"를 그대로 보여준다.
- **요약 문구와 상태 값은 그대로 둔다:** 의심 신호 발견 / 의심 신호 낮음 / 판단 보류, "참고 정보, 진위 단정 아님".
- **Gate 원인 문구:** 새 `mouth_unmeasurable`을 포함해 어르신이 읽을 말로 보여준다. 문구가 없는 코드는 기본 문구와 서버 메시지로 보여준다(지금과 같음).
- **진행 막대:** 실제 단계(Gate → WaveRep → MotionPhys → SyncNet)만 보여준다. 퍼센트는 만들지 않는다.
- **대상은 어르신이다.**
  - 본문 18px 이상
  - 회색 글자를 포함해 글자는 WCAG AA(4.5:1) 이상
  - 버튼은 56px 이상
  - 움직임 줄이기 설정을 존중하고, 앱 안에서도 끌 수 있게 한다
- **API 필드와 상태 값은 바꾸지 않는다.**

## 1. 화면 목록

| 화면 | 지금 | 바꾼 뒤 |
|---|---|---|
| 홈(입력) | 밝은 테마, 주소 입력 카드, 업로드 불가 안내 | 별빛 배경의 큰 굵은 제목(두 줄), 한 줄 설명, **링크 칸 하나 + "붙여넣기" 알약 버튼 + "확인하기" 알약 버튼**. 아래에 유리 카드 3장으로 "무엇을 보는지"(얼굴 화질 신호, 움직임, 입과 소리)를 글로만 설명한다. 스크롤하면 빛(스포트라이트)이 넓어지며 카드가 드러난다 |
| 진행 | 단계 행 목록 | 유리 카드 안에 4단계 표시(영상 확인·Gate / 화질 신호 / 움직임 / 입과 소리). 끝난 단계만큼 칸이 채워지는 **단계형** 그라데이션 막대. 각 단계 이름과 "진행 중 / 끝남 / 건너뜀"을 글자로 쓰고, 퍼센트는 없다. 취소 버튼 |
| 결과 요약 | 상태 라벨 + 제목 + 이유 + 분석 범위 | 맨 위에 상태 라벨(의심 신호 발견 / 낮음 / 판단 보류 / 분석하지 못함) + "참고 정보, 진위 단정 아님". 그 아래 **증거 3구역**: ① 분석한 구간 타임라인(Gate 적합·제외 구간, 제외 이유 글) ② 신호별 카드(WaveRep, MotionPhys, SyncNet의 상태와 "무엇을 봤는지" 한 줄) ③ "진짜 영상 범위와 비교" 자리(지금은 "비교 기준 준비 중 → 판단 보류") |
| 결과 상세 | 축별 원시 점수 숫자 | 구간·신호별 설명과 품질(얼굴 크기, 선명도). **원시 점수 숫자는 기본 화면에서 뺀다**. 아래 결정 D1 참조 |
| 이용 안내 | 네 가지 안내 | 같은 내용을 새 디자인으로. "숫자로 진위를 말하지 않는 이유" 한 단락 추가 |
| 세션(키 입력) | 지금 | 새 디자인만 적용. 기능은 그대로 |
| **시연용 녹화 결과 재생** | 없음 | 아래 §5. 맨 위에 늘 "시연용 녹화 결과" 띠를 보여준다 |

**결정 D1(사용자 확인 필요).** 상세 화면의 축별 "원시 점수" 숫자는 진짜 영상 범위와 비교한 값이 아니다. 규칙 3과 충돌 소지가 있다(0단계 충돌 목록 3번). 두 안이 있다.
- (가) 숫자를 화면에서 뺀다.
- (나) "연구용 원시 값(진위 확률 아님)" 접는 구역 안에만 둔다.

제안은 (가)다. 비교 기준(4단계)이 생기면 "범위 안 / 범위 밖"의 말로 보여준다.

## 3. 컴포넌트 (`app/lib/design/widgets.dart` 개편)

- `StarfieldBackground`: 고정 시드로 점을 그린다(CustomPainter). 움직임 줄이기에서는 정지 상태다.
- `SpotlightReveal`: 스크롤 위치에 따라 원형 빛의 반지름을 넓혀 아래 내용을 드러낸다. 움직임 줄이기에서는 처음부터 다 보인다(내용은 언제나 접근 가능하고 가리는 것은 장식뿐이다).
- `GlassCard`: 반투명 바탕과 얇은 테두리. 블러가 무거우면 단색으로 대체한다.
- `PillButton`(주·보조), `PasteLinkField`
  - 링크 칸은 하나다.
  - "붙여넣기" 버튼은 브라우저 클립보드 읽기를 시도하고, 권한이 없으면 "길게 눌러 붙여넣기" 안내 글을 보여준다.
- `StageProgress`: 4단계 칸 막대와 단계별 글자.
- `StatusBanner`: 상태 라벨과 "참고 정보, 진위 단정 아님".
- `EvidenceTimeline`: Gate 적합·제외 구간. 기존 분석 범위 카드를 개편하고, 길이를 모르면 그리지 않는 규칙을 유지한다.
- `SignalCard`: 축 상태와 설명 한 줄. 숫자 결론은 없다.
- `ComparisonPlaceholder`: "비교 기준 준비 중 → 판단 보류".
- `ReplayBanner`: "시연용 녹화 결과".
- `MotionToggle`: 화면 움직임 줄이기 켜고 끄기. 기본값은 OS 설정(`MediaQuery.disableAnimations`)을 따른다.

## 4. 접근성 점검 방법

1. **대비 단위 테스트:** 지금의 `design_test.dart` 방식을 쓴다. 위 표의 모든 글자 토큰을 `bg`, `bg2`, 유리 카드(최악 혼합색)에서 4.5:1 이상인지 검사한다. 조작 요소 테두리는 3:1 이상인지 검사한다.
2. **글자 크기:** 모든 `TText`가 16 이상이고 본문류가 18 이상인지 검사한다. 글자 배율 200%(`textScaler`)에서 화면별 overflow가 없는지 위젯 테스트로 확인한다.
3. **움직임 줄이기:** `disableAnimations=true`와 앱 토글에서 반복 애니메이션이 돌지 않는지, `SpotlightReveal`이 처음부터 내용을 보여주는지 테스트한다.
4. **터치·키보드:** 조작 요소가 56 이상인지, Tab 순서(링크 칸 → 붙여넣기 → 확인하기)와 초점 표시(`accent` 2px)를 테스트한다.
5. **화면 낭독기:** 장식(별·빛)은 `ExcludeSemantics`로 뺀다. 상태 라벨은 header로 둔다. 수동 확인은 macOS VoiceOver + Safari, Chrome Lighthouse 접근성 점수로 하고, 결과를 기록한다.
6. **사람 확인:** 사용자가 어르신 한 분께 홈 → 결과 흐름을 보여 드리고, 읽기 어려운 곳을 메모한다(선택).

## 5. 시연용 녹화 결과 재생 모드

- **빌드:** `TRINITY_API_MODE=replay`(새 값). 기존 `mock` 모드는 손으로 만든 결과(`overall_score` 0.87 등)가 있으므로 Pages 빌드에 쓰지 않는다.
- **녹화:** `scripts/record_demo.py`
  - 실제 서버 + Worker로 본인 영상(등록 테스트 링크)을 분석한다.
  - 상태 GET 응답 순서와 결과 GET 응답을 그대로 저장한다.
  - 저장 전에 허용 목록으로 걸러낸다:
    - `analysis_id` → `"recorded-1"`
    - `youtube_video_id` → `"recorded"`
    - 키, 헤더, URL, 시각(절대 시각 → 상대 초)은 빼거나 바꾼다
  - 걸러낸 뒤 검사기가 실패하면 저장하지 않는다. 검사 대상은 URL 패턴, `http`, 11자 ID 패턴, base64 이미지, 키 형식이다.
- **형식**(`app/assets/replay/<name>.json`, 커밋 대상)
```json
{
  "schema": 1,
  "label": "본인 촬영 A(가로 발화)",
  "recorded": {"date": "2026-11-2x", "server_commit": "abc1234", "gate_version": "gate-v2", "device": "M3 MPS"},
  "source": "real_run",
  "status_sequence": [{"after_sec": 0.0, "body": {"job_status": "queued", "stage": "validating"}}, "..."],
  "result": {"...": "결과 GET 응답 본문(걸러낸 것)"}
}
```
- **재생:**
  - `ReplayApi`가 `AnalysisApi` 인터페이스를 구현한다. 접수하면 녹화 목록에서 고르게 하고, `after_sec` 간격(배속 가능)으로 상태를 돌려준다.
  - 화면 맨 위에 "시연용 녹화 결과" 띠를 늘 보여준다.
  - 입력 칸은 쓰지 않고 녹화 선택 목록을 보여준다. Pages에는 다운로드 서버가 없기 때문이다.
- **넣지 않는 것:** 영상, 프레임, 얼굴 이미지, 키, URL, Seamless·참가자 합성 결과(합성물 비공개 결정). 본인 영상 결과만 넣는다.

## 6. GitHub Pages 배포

- 워크플로 `.github/workflows/pages.yml`
  - 트리거: `main` push와 수동 실행
  - 순서: Flutter 설치(버전 고정) → `flutter test` → `flutter build web --release --base-href /ai-/ --dart-define=TRINITY_API_MODE=replay` → `actions/upload-pages-artifact` → `actions/deploy-pages`
  - 권한: `pages: write`, `id-token: write`
- `app/web/index.html`에는 이미 `$FLUTTER_BASE_HREF` 자리가 있다. 위 빌드 인자로 `/ai-/`가 들어간다.
- 저장소 설정에서 Pages 소스를 "GitHub Actions"로 한 번 바꾼다. **사용자가 직접 할 일이다.**
- 배포 주소는 https://yeonje14.github.io/ai-/ 다. 공개 페이지이므로, 배포 전에 재생 JSON 검사기를 CI에서 다시 돌린다.
- 확인 필요: 저장소 공개 여부와 요금제에 따른 Pages 사용 가능 여부. 비공개 저장소의 Pages는 요금제에 따라 다르다.

## 8. 구현 순서(승인 뒤, 브랜치 `feat/web-redesign`, PR 하나)

1. 토큰과 대비 테스트
2. 컴포넌트(별·빛·유리·알약·진행)와 움직임 줄이기
3. 홈 → 진행 → 결과 → 상세 → 안내 순서로 화면 개편
4. 재생 모드와 녹화 스크립트·검사기, 녹화 1~2건(본인 영상)
5. Pages 워크플로
6. `docs/design-system.md`를 새 토큰으로 갱신한다(변경 기록 절 추가)
7. 전체 `flutter test`, analyze, 접근성 수동 확인 기록

**결정 필요**
- D1(원시 점수 숫자 처리)
- 재생 녹화 대상 영상(본인 A·B·E 중)
- 2단계 구현 뒤에 시작할지, 2단계와 병렬로 할지
