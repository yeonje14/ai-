## 1. 사전 조건 확인 결과 (2026-11-26)

| 항목 | 결과 |
|---|---|
| 공식 배포처 | MediaPipe Face Detector 문서(developers.google.com/edge/mediapipe/solutions/vision/face_detector)의 Models 절에 "BlazeFace (full-range)"가 사용 가능 모델로 올라 있다. 입력 192×192, float16. 문서 링크는 Hugging Face `litert-community/MediaPipe-FaceDetector-BlazeFace-Full-Range`를 가리킨다. 이 카드가 밝힌 원 출처는 `storage.googleapis.com/mediapipe-models/face_detector/blaze_face_full_range/float16/latest/blaze_face_full_range.tflite`다 |
| 받은 파일 | 원 출처 URL에서 받았다. `data/models/gate-candidates/blaze_face_full_range.tflite`(Git 제외 확인), 1,083,786바이트, SHA-256 `3698b18f063835bc609069ef052228fbe86d9c9a6dc8dcb7c7c2d69aed2b181b` |
| 이용 조건 | 문서 페이지에는 적혀 있지 않다. Hugging Face 카드에 따르면 "apache-2.0"이고, 같은 저장소에 있는 Google 모델 카드 PDF에 Apache License 2.0으로 적혀 있다고 한다. **PDF 원문은 아직 읽지 않았다. 채택 전에 확인한다** |
| Tasks API | MediaPipe 1.2.3의 `vision.FaceDetector`로 로드했고, 1프레임 추론에 성공했다. 본인 A 1프레임은 얼굴 1개(점수 0.99), pilot#0 B 1프레임은 얼굴 1개(점수 0.90)였다. short-range는 같은 프레임에서 0.97과 0.57이었다 |
| 대안 | Tasks API로 되므로 확인하지 않았다. 참고로 설치된 MediaPipe에는 옛 `solutions` API가 없다(`hasattr(mp, "solutions")`가 False). 타일 분할 방식은 검토하지 않았다 |
| Face Landmarker 내부 검출기 | 쓴다. `face_landmarker.task` 번들 안의 `face_detector.tflite`는 Gate의 short-range 파일과 SHA-256이 같다(`b4578f35…`). 따라서 검출기만 바꾸면 특징점 단계는 그대로이고, 측정 후보는 **Vab**(full-range 검출 + 그 박스 주변 crop 배율 3)다 |
| **박스 크기 차이** | 같은 pilot#0 B 프레임에서 full-range 박스 높이는 158px, short-range는 295px였다. 본인 A는 499px 대 495px였다. 박스 정의나 크기가 모델과 영상에 따라 다를 수 있다. 박스에 의존하는 다른 것들이 함께 바뀐다: Gate 품질 기준(`min_face_height_px` 96, 주된 얼굴 짧은 변 대비 0.10, 선명도 영역)과 crop 크기(박스 × 3) |

## 2. 검출 실패 원인 진단 (2026-11-26)

- 방법: S1-A, S2-A, S2-B, S3-B 전처리본에서 각각 3프레임(약 2, 10, 18초)을 저장소 밖 임시 폴더로 뽑아 직접 봤다. 분류만 기록했고 프레임은 지웠다.

| 영상 | 분류 | 메모 |
|---|---|---|
| S1-A | 얼굴이 작음 | 정면, 가림 없음, 배경 단색. 전신 구도에서 얼굴이 프레임 높이의 약 1/8 |
| S2-A | 얼굴이 작음 + 기타(역광) | 정면에 가깝다. 이 넷 중 얼굴이 가장 작다(프레임 높이의 약 1/14). 창가 강한 빛 |
| S2-B | 얼굴이 작음 + 고개 돌림(일부) | 안경. 위나 옆을 보는 장면이 있다 |
| S3-B | 얼굴이 작음 + 고개 돌림(일부) | 안경, 머리카락. 고개를 드는 장면이 있다. 대체로 정면 |

- 주원인은 얼굴이 작은 것이다. 네 영상 모두 해당한다. 고개 돌림은 일부 장면에만 있고, 가림이나 화면 밖은 보지 못했다.
- 그래서 "검출기를 바꿔도 효과가 제한적"인 경우에는 해당하지 않는다. 다만 표본이 영상당 3프레임뿐이다.

## 3. 측정 설계 (초안)

**변형**
- V2: 현행 서버(gate-v2. short-range 검출, 전체 프레임 특징점)
- **Vab**: full-range 검출 + 그 박스 중심 정사각형 crop(박스 긴 변 × 3, 고정)에 특징점. 가까운 박스가 없으면 전체 프레임
- 참고로만 재고 판정에는 쓰지 않는 것: Va(short-range + crop), Vb(full-range + 전체 프레임 특징점)
- Gate의 다른 설정(품질 임계값 포함)은 바꾸지 않는다. 박스 크기 차이의 영향은 그대로 드러나게 둔다.

**영상 묶음**

| 묶음 | 영상 |
|---|---|
| 개발용 | pilot#0 A·B, 예약 파일럿 1~3번 A·B(8개). 1~3번은 PR #40에서 결과를 봤으므로 이제 개발용이다 |
| 확인용 | 예약 파일럿 4~6번 A·B(6개). 기준 커밋·push 뒤에 받고, 측정 전에는 열어 보지 않는다 |
| 회귀 | 본인 촬영 A~E |

**지표:** PR #40의 지표에 다음을 더한다.
- 박스 높이 중앙값(검출기별)
- `face_too_small`·`no_face_detected`·`mouth_unmeasurable` 초
- 검출 단계 시간

**재현:** `scripts/gate_small_face_compare.py`에 검출 모델 인자와 Vb·Vab 변형을 더한다(1-B 시작 때 구현하고 테스트한다).

## 4. 채택 기준 초안 (Vab 대 V2, 승인 대기)

- **개발용**
  - pilot#0 B와 S3-A의 입 측정률 80% 이상. PR #40 Va에서는 72.5%, 76.6%였다.
  - 개발용 8개 전체에서 측정률이 2%p 넘게 떨어진 영상이 없음
- **확인용(4~6번, 영상마다)**
  - 측정률 하락 2%p 이하
  - V2 측정률이 80% 미만인 영상은 Vab 80% 이상. 그런 영상이 없으면 "개선 효과 확인 불가, 비회귀만 확인"
  - V2에 적합 구간이 있으면 Vab 적합 길이 감소 5% 이하
- **회귀(A~E)**
  - 측정률 하락 2%p 이하
  - C·D는 적합 0초, `no_mouth_movement`
  - A·B·E 적합 길이 변화 ±5% 이내, E 겹침 감소 1초 이하
  - 새 조건: `face_too_small`·`no_face_detected` 초가 늘지 않음. 박스 크기 차이 때문에 넣었다
- **공통**
  - Gate 시간 증가 20% 이하(3회 중앙값)
- **\|Δopening\| 기준 변경 제안**
  - 이 제안은 PR #40 결과(소형 얼굴 S0-B·S1-B에서 0.018)를 본 뒤 정한 것이다.
  - 회귀(본인 A~E, 큰 얼굴): 중앙값 0.01 이하를 유지한다.
  - Seamless 영상(소형 얼굴): 중앙값을 `mouth_min_swing`과 같은 0.02 이하로 완화하자고 제안한다.
  - 이유 1: 소형 얼굴에서 V2 값은 전체 프레임 특징점이 겨우 성공한 표본에서만 나온다. 그래서 차이가 곧 Vab의 오류라고 볼 근거가 없다. 프레임 단위 정답이 없어 어느 쪽이 맞는지 모른다.
  - 이유 2: 대신 오인식 위험은 C·D 유지(회귀)로 직접 확인한다.
  - 0.02는 입 움직임 반전 한 번의 크기다. 이보다 큰 체계적 차이는 판정을 바꿀 수 있어 상한으로 둔다.
  - 원래 기준(전체 0.01)을 유지할지는 사용자가 정한다.
- **판정**
  - 모두 통과하면 Vab 채택(§15.3 변경 문안)을 제안한다.
  - 하나라도 미달하면 미달 항목과 원인을 보고한다. 12-03 범위 축소 기준 적용 여부는 사용자가 정한다.
  - 결과를 본 뒤 기준을 바꾸지 않는다.

## 5. 승인 뒤 순서

1. 이 문서의 기준을 확정해 커밋·push한다.
2. `fetch_pilot.py --order 4·5·6`으로 받고 `seamless_preprocess.py --order N`으로 전처리한다.
3. "1-B 시작" 지시를 받으면 비교 스크립트를 확장하고(테스트 포함) 3회 측정한다. 결과는 `docs/gate.md`에 적는다.
4. 채택하면 모델 해시를 `configs/gate_models.json`에, 이용 조건을 `docs/licenses.md`에 기록한다. 서버 구현과 §15.3 변경은 그다음이다.
